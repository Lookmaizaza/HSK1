# บทที่ 2
# ภาพรวมโครงงานสหกิจศึกษา

## 2.1 ความเป็นมาและความสำคัญของปัญหา

**ความเป็นมาก่อนเข้าปัญหา**  
ในยุคโลกาภิวัตน์ปัจจุบัน ภาษาจีนกลาง (Mandarin Chinese) ได้ทวีบทบาทและความสำคัญอย่างยิ่งยวด ทั้งในด้านการค้า เศรษฐกิจ การต่างประเทศ นวัตกรรมเทคโนโลยี และความร่วมมือทางการศึกษาระดับนานาชาติ สำหรับประเทศไทยซึ่งมีความสัมพันธ์ทางเศรษฐกิจและวัฒนธรรมอันแน่นแฟ้นกับสาธารณรัฐประชาชนจีน ความต้องการบุคลากรที่มีความรู้ความสามารถในการสื่อสารภาษาจีนกลางจึงมีอัตราการเติบโตขึ้นอย่างก้าวกระโดด ส่งผลให้การสอบวัดระดับความรู้ภาษาจีนมาตรฐานสากล (Hànyǔ Shuǐpíng Kǎoshì: HSK) ถูกนำมาใช้เป็นเกณฑ์ชี้วัดมาตรฐานความสามารถทางภาษาของนักเรียน นักศึกษา และบุคลากรวิชาชีพอย่างกว้างขวาง โดยหัวใจสำคัญของการสื่อสารภาษาจีนให้สัมฤทธิผลนั้น ขึ้นอยู่กับทักษะการออกเสียงที่ถูกต้อง แม่นยำ และเป็นธรรมชาติ ซึ่งเป็นรากฐานสำคัญที่สุดในการสร้างความเข้าใจและการสื่อสารที่มีประสิทธิภาพ

**อธิบายปัญหาที่เกิด เกิดแล้วมีผลเสียอย่างไร**  
อย่างไรก็ตาม ผู้เรียนชาวไทยที่เริ่มต้นเรียนภาษาจีนกลางต้องเผชิญกับอุปสรรคสำคัญอันเนื่องมาจากความแตกต่างอย่างมีนัยสำคัญของระบบหน่วยเสียงและวรรณยุกต์ (Phonological and Tonal Discrepancies) ระหว่างภาษาไทยและภาษาจีนกลาง โดยปัญหาหลักที่เกิดขึ้นและส่งผลเสียต่อการเรียนรู้มีดังนี้:

1. **ปัญหาความสับสนของระดับเสียงวรรณยุกต์ (Tone Confusion) และปรากฏการณ์ Tone Sandhi:** ภาษาจีนกลางเป็นภาษาที่มีวรรณยุกต์บอกความหมายของคำ (Lexical Tone Language) โดยเฉพาะความสับสนระหว่างวรรณยุกต์เสียงที่ 2 (阳平 - Yángpíng: เสียงขึ้น ระดับ 35) และวรรณยุกต์เสียงที่ 3 (上声 - Shǎngshēng: เสียงต่ำ-หักเลี้ยว ระดับ 214) ซึ่งผู้เรียนชาวไทยมักออกเสียงวรรณยุกต์เสียงที่ 3 ไม่ลึกพอ โดยไม่สามารถกดระดับความถี่มูลฐาน ($F_0$) ลงถึงระดับ 1 ตามระบบระดับเฉา (Chao Tone Scale: 1–5) ได้ ทำให้เสียงลอยขึ้นกลายเป็นวรรณยุกต์เสียงที่ 2 ส่งผลให้ความหมายของคำแปรเปลี่ยนไปโดยสิ้นเชิง ยิ่งไปกว่านั้น เมื่อเกิดปรากฏการณ์การแปรผันของวรรณยุกต์ (Tone Sandhi) เช่น วรรณยุกต์เสียง 3 ซ้อนเสียง 3 ($3 + 3 \rightarrow 2 + 3$) ผู้เรียนมักผันเสียงผิดพลาดจนทำให้การสื่อสารล้มเหลว
2. **ปัญหาการออกเสียงพยัญชนะเฉพาะกลุ่ม:** ผู้เรียนชาวไทยมักมีอัตราความผิดพลาดในการออกเสียงแทนที่ (Substitution Error) สูงมากในกลุ่มพยัญชนะลิ้นม้วน (Retroflex: *zh, ch, sh, r*) โดยมักออกเสียงกลายเป็นกลุ่มพยัญชนะปลายลิ้นแตะฟัน (Dental Sibilant: *z, c, s*) รวมถึงความสับสนในกลุ่มพยัญชนะหน้าเพดานแข็ง (Alveolo-palatal: *j, q, x*) เนื่องจากเป็นหน่วยเสียงที่ไม่มีในระบบสัทศาสตร์ภาษาไทย
3. **ข้อจำกัดของการจัดการเรียนการสอนแบบดั้งเดิม:** การเรียนในชั้นเรียนที่มีผู้เรียนจำนวนมาก ผู้สอนไม่สามารถรับฟังและให้ข้อมูลสะท้อนกลับ (Feedback) เชิงลึกแก่ผู้เรียนเป็นรายบุคคลได้อย่างทันท่วงที ทำให้ผู้เรียนจดจำรูปแบบการออกเสียงที่ผิดพลาดซ้ำ ๆ จนกลายสภาพเป็นข้อผิดพลาดถาวร (Fossilization)
4. **ข้อจำกัดของแอปพลิเคชันฝึกภาษาในปัจจุบันและความเสี่ยงด้านความเป็นส่วนตัว:** แอปพลิเคชันช่วยฝึกภาษาทั่วไปมักทำงานในลักษณะ "กล่องดำ" (Black Box) โดยแสดงผลเพียงคะแนนรวมแบบเปอร์เซ็นต์หยาบ ๆ ปราศจากการวิเคราะห์เจาะลึกระดับหน่วยเสียง (Phoneme Level) ขาดการแสดงเส้นโค้งระดับเสียง (Pitch Contour) ที่เปรียบเทียบกับเจ้าของภาษาแบบเรียลไทม์ และที่สำคัญที่สุดคือ ระบบส่วนใหญ่ขาดการบันทึกข้อมูลพฤติกรรมการเรียนรู้ตามมาตรฐานสากล เช่น IEEE 9274.1.1 (xAPI) และมีความเสี่ยงต่อการละเมิดพระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (PDPA) จากการจัดเก็บไฟล์เสียงชีวมิติ (Voice Biometrics) ของผู้เรียนลงบนเซิร์ฟเวอร์โดยไม่จำเป็น

**อธิบายงานของตนเองว่าจะทำอะไร มีแนวคิดอย่างไร ทำอย่างไร ทำแล้วจะช่วยแก้ปัญหาอย่างไร ดีขึ้นอย่างไร**  
เพื่อแก้ไขปัญหาดังกล่าว ผู้จัดทำจึงได้ดำเนินโครงงาน **"การพัฒนาแอปพลิเคชันการเรียนรู้ภาษาจีนสำหรับผู้เรียนชาวไทย โดยประยุกต์ใช้ระบบตรวจสอบเสียงด้วยปัญญาประดิษฐ์" (ภายใต้ชื่อระบบ "语 ปากจีน" - Yupakjeen)** โดยมีแนวคิดในการพัฒนานวัตกรรมแพลตฟอร์มการเรียนรู้ที่บูรณาการระบบตรวจสอบเสียงด้วยปัญญาประดิษฐ์ สัทศาสตร์เชิงคำนวณ กลไกเกมมิฟิเคชัน และการวิเคราะห์การเรียนรู้เข้าด้วยกัน

วิธีการดำเนินการมีดังนี้:
1. พัฒนาโมเดลปัญญาประดิษฐ์แบบการเรียนรู้เชิงลึกขนาดเบา สถาปัตยกรรม 1D Convolutional Neural Network ร่วมกับ Bidirectional Long Short-Term Memory (1D-CNN + Bi-LSTM) ที่ผ่านการฝึกสอนด้วยชุดข้อมูล AISHELL-3 เพื่อจำแนกวรรณยุกต์ 4 เสียงได้อย่างแม่นยำสูง และสามารถรันบนเบราว์เซอร์ผ่าน ONNX Runtime Web ด้วยความเร็วไม่เกิน 15 มิลลิวินาที
2. พัฒนาระบบวิเคราะห์เส้นโค้งระดับเสียง (Pitch Contour Analysis) แบบเรียลไทม์ผ่าน Web Audio API โดยประยุกต์ใช้อัลกอริทึม YIN สำหรับประมาณค่าความถี่มูลฐาน ($F_0$), คำนวณความชัดเจน (Clarity 0.0–1.0), แปลงเป็นระดับเฉา (Chao Scale: 1–5), ระบุ Slope 5 ประเภท (flat, rising, dipping, falling, neutral) และตรวจจับ Tone Sandhi
3. พัฒนาหลักสูตรคำศัพท์มาตรฐาน HSK 1–3 จำนวนกว่า 1,000 คำ ในรูปแบบ Quest-based Learning จำนวน 126 ด่าน โดยใช้หลักการ Listen-Before-Speak และ Input Hypothesis (Krashen, 1982) ร่วมกับกลไก Gamification (XP, Hearts, Streak)
4. พัฒนาระบบวินิจฉัยข้อผิดพลาดแบบปรับตัว (Adaptive Diagnostic System) ที่วิเคราะห์ค่า PER, GOP และจำแนกประเภทความผิดพลาด (substitution, omission, insertion, correct) ในกลุ่มพยัญชนะ Retroflex, Alveolo-palatal และ Dental Sibilant เพื่อแนะนำแบบฝึกหัดซ่อมเสริมเฉพาะบุคคล
5. วางสถาปัตยกรรมการไหลของข้อมูล telemetry ตามมาตรฐานสากล IEEE 9274.1.1 (xAPI) ครอบคลุม 3 เหตุการณ์ (`pronounced`, `listened_to_example`, `hesitated`) จัดเก็บบนฐานข้อมูล Turso (libSQL) ภายใต้หลักการ Zero Audio Storage at Rest เพื่อคุ้มครองข้อมูลส่วนบุคคลตามกฎหมาย PDPA

การดำเนินงานนี้จะช่วยให้ผู้เรียนชาวไทยมองเห็นระดับเสียงของตนเองเปรียบเทียบกับเจ้าของภาษาแบบเรียลไทม์ ทราบจุดบกพร่องระดับหน่วยเสียงและวรรณยุกต์ได้อย่างแม่นยำ ได้รับการแก้ไขข้อผิดพลาดอย่างตรงจุด มีแรงจูงใจในการฝึกฝนอย่างสม่ำเสมอ และช่วยให้เกิดคลังข้อมูลพฤติกรรมการเรียนรู้มาตรฐานที่ปลอดภัยตามกฎหมาย PDPA

## 2.2 วัตถุประสงค์ของโครงงานสหกิจศึกษา

การวิจัยและพัฒนาโครงงานสหกิจศึกษาในครั้งนี้ มีวัตถุประสงค์หลักเพื่อพิสูจน์และสร้างองค์ความรู้ใน 5 ประการ ดังต่อไปนี้:

1. เพื่อออกแบบและฝึกสอนโมเดลปัญญาประดิษฐ์ประเภท Lightweight Deep Learning สถาปัตยกรรม 1D Convolutional Neural Network ร่วมกับ Bidirectional Long Short-Term Memory (1D-CNN + Bi-LSTM) สำหรับจำแนกวรรณยุกต์ภาษาจีนกลาง 4 ระดับ โดยมีค่าความแม่นยำในการจำแนก (Classification Accuracy) ไม่ต่ำกว่าร้อยละ 85 และมีเวลาอนุมาน (Inference Latency) บนเบราว์เซอร์ผ่าน ONNX Runtime Web ไม่เกิน 15 มิลลิวินาทีต่อครั้ง
2. เพื่อออกแบบและพัฒนาระบบวิเคราะห์เส้นโค้งระดับเสียง (Pitch Contour Analysis) แบบเรียลไทม์ผ่าน Web Audio API โดยประยุกต์ใช้อัลกอริทึม YIN สำหรับประมาณค่าความถี่มูลฐาน (Fundamental Frequency: $F_0$) และแปลงเป็นระดับเฉา (Chao Tone Scale: 1–5) พร้อมทั้งตรวจจับปรากฏการณ์ Tone Sandhi ที่พบในภาษาจีนกลาง โดยระบบต้องมีค่าความชัดเจนของสัญญาณ (Clarity) ที่คำนวณได้จากฟังก์ชัน Periodicity ของอัลกอริทึม YIN อยู่ในช่วง 0.0–1.0 และสามารถระบุรูปแบบ Slope ของเส้นโค้งได้ถูกต้องทั้ง 5 ประเภท ได้แก่ flat, rising, dipping, falling และ neutral
3. เพื่อออกแบบและพัฒนาหลักสูตรการเรียนรู้แบบ Quest-based Learning ตามกรอบมาตรฐาน HSK ระดับ 1, 2 และ 3 ครอบคลุมคำศัพท์ไม่น้อยกว่า 1,000 คำ จัดแบ่งเป็นไม่น้อยกว่า 126 ด่าน พร้อมระบบ Gamification ที่ประกอบด้วยคะแนนสะสม (XP) ระบบชีวิต (Hearts) และการนับวันเรียนต่อเนื่อง (Streak) โดยลำดับกิจกรรมการเรียนรู้ในแต่ละด่านอ้างอิงหลักการ Listen-Before-Speak และ Input Hypothesis (Krashen, 1982) ซึ่งผู้เรียนต้องรับฟังเสียงต้นแบบก่อนการออกเสียงทุกครั้ง
4. เพื่อพัฒนาระบบวินิจฉัยข้อผิดพลาดและแนะนำเนื้อหาแบบปรับตัว (Adaptive Diagnostic System) ที่วิเคราะห์ข้อผิดพลาดในระดับหน่วยเสียงผ่านค่า Phoneme Error Rate (PER) และประเมินคุณภาพการออกเสียงผ่านคะแนน Goodness of Pronunciation (GOP) ระดับ phoneme โดยระบบสามารถระบุรูปแบบข้อผิดพลาด (Error Pattern) ได้อย่างน้อย 4 ประเภท ได้แก่ substitution, omission, insertion และ correct และจำแนกจุดอ่อนของผู้เรียนในกลุ่มพยัญชนะต้น 3 กลุ่ม ได้แก่ Retroflex (*zh, ch, sh, r*), Alveolo-palatal (*j, q, x*) และ Dental Sibilant (*z, c, s*) ตลอดจนความผิดพลาดด้านวรรณยุกต์ทั้ง 4 ระดับ
5. เพื่อออกแบบระบบบันทึกและจัดเก็บข้อมูลพฤติกรรมการเรียนรู้ตามมาตรฐาน IEEE 9274.1.1 (xAPI) บนฐานข้อมูล Turso (libSQL) ภายใต้หลักการ Zero Audio Storage at Rest ตามพระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (PDPA) โดยระบบต้องสามารถแปลงข้อมูลพฤติกรรมการเรียนรู้เป็น xAPI Statement ได้ครบทั้ง 3 ประเภท ได้แก่ `pronounced`, `listened_to_example` และ `hesitated` พร้อมบันทึกตัวชี้วัดเชิงพฤติกรรม ได้แก่ จำนวนครั้งที่ฟังเสียงต้นแบบ (LQ5: Listening Impact) และค่าความล่าช้าก่อนบันทึกเสียง (LQ6: Hesitation Latency) เพื่อสนับสนุนการวิเคราะห์ผลการเรียนรู้ในระยะยาว

## 2.3 ขอบเขตของโครงงานสหกิจศึกษา

การกำหนดขอบเขตของโครงงานสหกิจศึกษาเพื่อให้การดำเนินงานมีความชัดเจนและครอบคลุมทุกมิติ ได้จัดแบ่งขอบเขตออกเป็นด้านต่าง ๆ โดยมีรายละเอียดดังต่อไปนี้:

1. **สิทธิของผู้ใช้งานระบบ (User Roles & Permissions)**
   - **ผู้เรียน (Learner):** มีสิทธิ์จัดการความยินยอม PDPA, เข้าเรียนตามหลักสูตร 126 ด่าน, ฝึกออกเสียงและรับผลวิเคราะห์ F0, Chao Scale, Clarity และคะแนน GOP แบบเรียลไทม์, ตรวจสอบจุดอ่อนตนเองผ่านแดชบอร์ด และใช้สิทธิ์ขอเพิกถอนหรือลบข้อมูลส่วนบุคคล (Right to Erasure)
   - **ผู้สอนและนักวิจัย (Instructor & Researcher):** มีสิทธิ์เข้าถึงแดชบอร์ดภาพรวมของผู้เรียนระดับกลุ่ม (Cohort Analytics), เมทริกซ์ความผิดพลาดของหน่วยเสียงและวรรณยุกต์ (Confusion Matrix), และส่งออกข้อมูล xAPI Statements ในรูปแบบนิรนาม
   - **ผู้ดูแลระบบ (Administrator):** มีสิทธิ์ดูแลคลังข้อมูล Turso (libSQL), ตรวจสอบความพร้อมของระบบ และตรวจสอบบันทึกความยินยอม (Consent Audit Logs)
2. **ส่วนของการจัดการข้อมูล (Data Management)**
   - แปลงและจัดเก็บข้อมูลพฤติกรรมการเรียนรู้ตามมาตรฐานสากล IEEE 9274.1.1 (xAPI) ครอบคลุม 3 เหตุการณ์: `pronounced`, `listened_to_example` และ `hesitated`
   - จัดเก็บบนฐานข้อมูล Turso (libSQL) ในรูปแบบ Statement กึ่งโครงสร้าง JSON ร่วมกับดัชนีระบุตัวผู้เรียน
3. **ส่วนของการสมัครสมาชิก (User Registration)**
   - การลงทะเบียนและระบุตัวตนของผู้ใช้ผ่าน Anonymous UUID เพื่อตัดการเชื่อมโยงกับข้อมูลระบุตัวตนโดยตรง (PII)
4. **ส่วนของการลงชื่อเข้าใช้ (User Authentication & PDPA Consent)**
   - ระบบลงชื่อเข้าใช้งานที่เชื่อมโยงกับระบบจัดการความยินยอมตามเกณฑ์ PDPA (In-App Explicit Consent Form) แยกความยินยอมด้านการประมวลผลเสียงเพื่อการเรียนรู้และการยินยอมนำข้อมูลไปวิเคราะห์เพื่อการวิจัย พร้อมกลไก Consent Gatekeeper
5. **ส่วนของการสืบค้นข้อมูล (Data Querying & Telemetry Analytics)**
   - สืบค้นและประมวลผลสถิติผลการเรียนรู้รายบุคคลและรายกลุ่ม ได้แก่ ประวัติคะแนน GOP, PER, TER, ความล่าช้าก่อนบันทึกเสียง (Hesitation Latency: LQ6) และจำนวนครั้งในการฟังเสียงต้นแบบ (Listening Impact: LQ5)
6. **ส่วนของการออกรายงาน (Reporting & Diagnostic Dashboard)**
   - แสดงผลกราฟเปรียบเทียบเส้นโค้งระดับเสียง F0 ระหว่างเสียงผู้เรียนกับเจ้าของภาษาแบบเรียลไทม์
   - แสดงแผนผังจำแนกประเภทข้อผิดพลาดระดับหน่วยเสียง (PER) และตารางเมทริกซ์สับสนของวรรณยุกต์ (Tone Confusion Matrix)
   - ส่วนแนะนำบทเรียนและคำศัพท์ซ่อมเสริมแบบปรับตัว (Adaptive Remedial Recommendation)
7. **ส่วนของการทำงานของระบบ (System Processing Pipeline)**
   - การประมวลผลสัญญาณเสียงเรียลไทม์บนเบราว์เซอร์ผ่าน Web Audio API และอัลกอริทึม YIN
   - การรันโมเดลปัญญาประดิษฐ์ 1D-CNN + Bi-LSTM ผ่าน ONNX Runtime Web (WASM/WebGL) บนเครื่องฝั่งผู้เรียน (Inference Latency $\le 15$ ms)
   - สถาปัตยกรรมการไหลของข้อมูลแบบ Zero Audio Storage at Rest โดยประมวลผลบน RAM และทำลายไฟล์เสียงทันที ไม่มีการบันทึกไฟล์เสียงดิบลงสื่อจัดเก็บข้อมูลถาวร
8. **ทฤษฎีที่ใช้ในการพัฒนาระบบ**
   - ทฤษฎีสัทศาสตร์ภาษาจีนและระบบระดับเสียงเฉา (Chao Tone Scale: 1–5)
   - ทฤษฎีการเปิดรับภาษา (Input Hypothesis) ของ Stephen Krashen (1982)
   - ทฤษฎีการประมวลผลสัญญาณเสียงและอัลกอริทึม YIN
   - ทฤษฎีโครงข่ายประสาทเทียม 1D-CNN และ Bi-LSTM สำหรับอนุกรมเวลา
   - มาตรฐานข้อมูล IEEE 9274.1.1 (xAPI) และพระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (PDPA)

## 2.4 ประโยชน์ที่คาดว่าจะได้รับ

เมื่อการวิจัยและพัฒนาโครงงานสหกิจศึกษาครั้งนี้สำเร็จเสร็จสิ้น จะก่อให้เกิดประโยชน์ที่สอดคล้องกับวัตถุประสงค์การวิจัยทั้ง 5 ประการ โดยมีรายละเอียดดังต่อไปนี้:

1. **ด้านเทคโนโลยีปัญญาประดิษฐ์และการประมวลผลเสียง:** ได้โมเดลปัญญาประดิษฐ์ 1D-CNN + Bi-LSTM ขนาดเบาที่มีความแม่นยำในการจำแนกวรรณยุกต์ไม่ต่ำกว่าร้อยละ 85 และประมวลผลบนเบราว์เซอร์ได้รวดเร็วภายใน 15 มิลลิวินาที ทำให้ระบบตอบสนองผลการประเมินได้ทันทีโดยไม่ต้องพึ่งพาเซิร์ฟเวอร์ราคาแพง
2. **ด้านการวิเคราะห์สัทศาสตร์เชิงลึก:** ได้ระบบวิเคราะห์เส้นโค้งระดับเสียง $F_0$ และสเกลเฉา (Chao Scale 1–5) แบบเรียลไทม์ที่มีความชัดเจน (Clarity 0.0–1.0) พร้อมทั้งตรวจจับปรากฏการณ์ Tone Sandhi ได้อย่างถูกต้อง ทำให้ผู้เรียนมองเห็นความผิดพลาดของระดับเสียงตนเองได้อย่างเป็นรูปธรรม
3. **ด้านการจัดการเรียนรู้ภาษาจีน:** ได้หลักสูตรการเรียนรู้แบบ Quest-based Learning HSK 1–3 จำนวนกว่า 1,000 คำ ครอบคลุม 126 ด่าน ที่ผสานหลักการ Listen-Before-Speak และระบบ Gamification (XP, Hearts, Streak) ช่วยลดความวิตกกังวลและเพิ่มแรงจูงใจในการฝึกฝนภาษาอย่างต่อเนื่อง
4. **ด้านการวินิจฉัยและพัฒนาผู้เรียนเฉพาะบุคคล:** ได้ระบบวินิจฉัยข้อผิดพลาดแบบปรับตัว (Adaptive Diagnostic System) ที่จำแนกข้อบกพร่องในกลุ่มพยัญชนะ Retroflex, Alveolo-palatal และ Dental Sibilant รวมถึงวรรณยุกต์ 4 เสียง พร้อมแนะนำบทเรียนซ่อมเสริมอย่างตรงจุด ส่งผลให้ค่า PER และ TER ของผู้เรียนลดลงอย่างมีนัยสำคัญ
5. **ด้านมาตรฐานข้อมูลและความปลอดภัยของข้อมูลส่วนบุคคล:** ได้ระบบบันทึกข้อมูลพฤติกรรมการเรียนรู้ตามมาตรฐานสากล IEEE 9274.1.1 (xAPI) บนฐานข้อมูล Turso (libSQL) ภายใต้นโยบาย Zero Audio Storage at Rest ตามกฎหมาย PDPA ซึ่งเป็นต้นแบบที่ปลอดภัยและสามารถนำข้อมูล Telemetry ไปศึกษาวิจัยต่อยอดในระดับนานาชาติได้

## 2.5 ขั้นตอนและวิธีการดำเนินงาน

การกำหนดขั้นตอนการดำเนินการของ **ระบบแอปพลิเคชันการเรียนรู้ภาษาจีนสำหรับผู้เรียนชาวไทย โดยประยุกต์ใช้ระบบตรวจสอบเสียงด้วยปัญญาประดิษฐ์ ("语 ปากจีน")** เพื่อให้เข้าใจและทราบถึงการทำงานที่ถูกต้องตามหลักวิศวกรรมซอฟต์แวร์และการวิจัย จึงได้มีการกำหนดขั้นตอนในการศึกษาดังรายละเอียดต่อไปนี้:

1. **กำหนดเป้าหมายและวางแผนโครงการ (Project Planning Phase)**
   - ศึกษาบริบทการเรียนการสอนภาษาจีน ปัญหาทางสัทศาสตร์ของผู้เรียนไทย และโครงสร้างคำศัพท์ HSK 1–3
   - กำหนดวัตถุประสงค์การวิจัย 5 ประการ กรอบคำถามวิจัย (LQ1–LQ8) และนิยามตัวชี้วัดสัทศาสตร์
   - วางแผนการดำเนินงาน 16 สัปดาห์ และจัดทำโครงสร้างการแบ่งงาน (Work Breakdown Structure: WBS)
2. **วิเคราะห์ระบบการทำงาน (Analysis Phase)**
   - วิเคราะห์ข้อกำหนดของอัลกอริทึม YIN สำหรับการสกัด $F_0$ และเกณฑ์การแปลงเป็น Chao Scale 1–5
   - วิเคราะห์ข้อจำกัดทางเทคนิคของสถาปัตยกรรมโมเดล Deep Learning สำหรับรันบน ONNX Runtime Web (Latency $\le$ 15 ms)
   - วิเคราะห์มาตรฐานข้อมูล xAPI (IEEE 9274.1.1) และข้อกำหนดพระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (PDPA)
3. **ออกแบบระบบการทำงาน (Design Phase)**
   - ออกแบบสถาปัตยกรรมโมเดล 1D-CNN + Bi-LSTM และไปป์ไลน์การเทรนด้วยชุดข้อมูล AISHELL-3
   - ออกแบบอัลกอริทึมการระบุ Slope 5 ประเภท (flat, rising, dipping, falling, neutral) และกฎ Tone Sandhi
   - ออกแบบหลักสูตร Quest-based 126 ด่าน (HSK 1–3) และระบบ Gamification (XP, Hearts, Streak) ตามหลัก Listen-Before-Speak
   - ออกแบบโครงสร้าง xAPI Telemetry Schema (pronounced, listened_to_example, hesitated) และฐานข้อมูล Turso (libSQL)
   - ออกแบบส่วนต่อประสานผู้ใช้งาน (UI/UX Flow) ของหน้าจอฝึกออกเสียงและ Adaptive Diagnostic Dashboard
4. **พัฒนาระบบ (Implementation Phase)**
   - ฝึกสอนโมเดล 1D-CNN + Bi-LSTM ด้วย PyTorch และแปลงโมเดลเป็นฟอร์แมต ONNX
   - พัฒนาระบบประมวลผลเสียงเรียลไทม์ Web Audio API ร่วมกับอัลกอริทึม YIN บนฝั่งเบราว์เซอร์
   - พัฒนาเว็บแอปพลิเคชันส่วนหน้าด้วย SvelteKit, TypeScript และ Tailwind CSS ครอบคลุมระบบเควสต์ 126 ด่าน
   - พัฒนาระบบวินิจฉัยข้อผิดพลาด (PER, GOP) และ Adaptive Remedial Recommendation Engine
   - พัฒนาระบบบันทึก telemetry xAPI เชื่อมต่อกับฐานข้อมูล Turso (libSQL) และระบบ Consent Gatekeeper
5. **ทดสอบระบบ (Testing Phase)**
   - ทดสอบความแม่นยำในการจำแนกวรรณยุกต์ ($\ge 85\%$) และวัดเวลาการอนุมาน ($\le 15$ ms) บน ONNX Runtime Web
   - ทดสอบความถูกต้องในการสกัด $F_0$, ค่า Clarity (0.0–1.0), การแปลง Chao Scale, และการตรวจจับ Slope ของอัลกอริทึม YIN
   - ทดสอบความถูกต้องในการสร้าง Statement xAPI ครบทั้ง 3 ประเภท และการจัดเก็บบนฐานข้อมูล Turso
   - ทดสอบความปลอดภัยตามหลักการ Zero Audio Storage at Rest เพื่อยืนยันว่าไม่มีการบันทึกไฟล์เสียงดิบลงดิสก์
   - ดำเนินการทดสอบนำร่องกับกลุ่มผู้เรียนชาวไทยเพื่อประเมินความถูกต้องทางสัทศาสตร์และความพึงพอใจในการใช้งาน
6. **เรียบเรียงและจัดทำเอกสารประกอบการทำงาน (Documentation Phase)**
   - จัดทำเอกสารข้อกำหนดเชิงเทคนิค เอกสารสเปก API และพจนานุกรมข้อมูล (Data Dictionary)
   - เรียบเรียงและจัดทำรายงานโครงงานสหกิจศึกษาฉบับสมบูรณ์ โปสเตอร์ และสื่อนำเสนอผลงาน
7. **การบำรุงรักษาระบบ (Maintenance Phase)**
   - ติดตั้งและนำระบบขึ้นสู่สภาพแวดล้อมการใช้งานจริง (Deployment)
   - ตรวจสอบประสิทธิภาพการสืบค้นข้อมูลบนฐานข้อมูล Turso และแก้ไขข้อบกพร่องตามผลตอบรับของผู้เรียน

จากขั้นตอนที่กล่าวมาข้างต้น สามารถแสดงแผนปฏิบัติงานโครงงานโดยแบ่งออกเป็นงานย่อย ๆ (กิจกรรมของแต่ละขั้นตอน) เวลาเริ่มต้นงาน เวลาสิ้นสุดงาน จำนวนวันที่ทำงาน รวมถึงงานที่ต้องทำก่อนหน้า ดังแสดงในตารางที่ 2.1 และแสดงระยะเวลาดำเนินการในรูปแบบ Gantt Chart ดังรูปที่ 2.1
