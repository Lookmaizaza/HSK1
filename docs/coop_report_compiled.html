บทคัดย่อ

โครงงานสหกิจศึกษานี้มีวัตถุประสงค์เพื่อออกแบบและพัฒนาระบบวิเคราะห์ข้อมูลการเรียนรู้ (Learning Analytics) ระบบจัดเก็บข้อมูลพฤติกรรมการเรียนรู้ตามมาตรฐาน Experience API (xAPI / IEEE 9274.1.1) โมเดลติดตามความเชี่ยวชาญและแนะนำบทเรียนซ่อมเสริมรายบุคคล (Mastery Tracking & Adaptive Remedial Recommendation Engine) ตลอดจนแดชบอร์ดวินิจฉัยเชิงสัทศาสตร์สำหรับผู้เรียนและผู้สอน ภายใต้สถาปัตยกรรมการคุ้มครองข้อมูลส่วนบุคคลที่ไม่จัดเก็บไฟล์เสียงดิบของผู้เรียนลงในฐานข้อมูลถาวร (PDPA Zero Audio Storage at Rest) โดยบูรณาการร่วมกับเว็บแอปพลิเคชันฝึกออกเสียงภาษาจีนกลาง "语 ปากจีน" (HSK 1–3)

การดำเนินงานแบ่งออกเป็น 4 ส่วนหลักตามแผนปฏิบัติงาน 16 สัปดาห์ ได้แก่ (1) การกำหนดคำถามการเรียนรู้ (Learning Questions: LQ1–LQ8) และการออกแบบโครงสร้างข้อมูล xAPI Telemetry Schema ร่วมกับคลังข้อมูลแบบสองชั้น (Dual-Database Architecture) บนฐานข้อมูล Turso (libSQL) และ Neon (PostgreSQL) พร้อมระบบคัดกรองความยินยอม (PDPA Consent Gatekeeper) (2) การสร้างอนุกรมวิธานความผิดพลาดทางสัทศาสตร์ (Error Taxonomy) ที่จำแนกความคลาดเคลื่อนออกเป็น 4 สถานะ (Correct, Substitution, Omission, Insertion) ร่วมกับการคำนวณตัววัดคุณภาพการออกเสียงเชิงตัวเลข ได้แก่ คะแนนความแม่นยำระดับหน่วยเสียง (Goodness of Pronunciation: GOP) อัตราความผิดพลาดของหน่วยเสียง (Phoneme Error Rate: PER) และคะแนนความแม่นยำของรูปร่างวรรณยุกต์ตามมาตรวัดของจ้าว หยวนเริ่น (Chao's Pitch Scale 1–5) (3) การพัฒนาโมเดลผู้เรียนด้วยการถ่วงน้ำหนักค่าเฉลี่ยเคลื่อนที่แบบเอ็กซ์โพเนนเชียล (Exponential Moving Average: EMA) ร่วมกับสมการเส้นโค้งการลืมของเอ็บบิงเฮาส์ (Ebbinghaus Forgetting Curve) และระบบแนะนำคำศัพท์ซ่อมเสริมอัตโนมัติที่จับคู่หน่วยเสียงพยัญชนะต้นและวรรณยุกต์ที่เป็นจุดอ่อนของผู้เรียน และ (4) การพัฒนาแดชบอร์ดสำหรับผู้เรียน (6-Axis Student Skill Radar และ AI Coach) และแดชบอร์ดสำหรับผู้สอน/ผู้ดูแลระบบ (Instructor & Cohort Diagnostic Dashboard จำนวน 12 มุมมอง)

ผลการดำเนินงานและการประเมินผลจากข้อมูลการใช้งานนำร่องและชุดข้อมูลทดสอบผู้เรียนจำนวน 100 คน พบว่าระบบสามารถดักจับ แปลง และจัดเก็บข้อมูล xAPI Statement ได้อย่างถูกต้องครบถ้วน 100% โดยไม่มีการจัดเก็บไฟล์เสียงดิบลงฐานข้อมูล ผลการวิเคราะห์เปรียบเทียบคะแนนทดสอบก่อนเรียนและหลังเรียน (Pre-test / Post-test) ด้วยสถิติ Paired Sample $t$-test แสดงให้เห็นว่าผู้เรียนมีพัฒนาการด้านความแม่นยำในการออกเสียงเพิ่มขึ้นอย่างมีนัยสำคัญทางสถิติที่ระดับ $.01$ ($p < .001$) โดยมีขนาดอิทธิพล (Cohen's $d$) อยู่ในระดับสูง และมีค่าพัฒนาการสัมพัทธ์ (Hake's Normalized Gain: $\langle g \rangle$) อยู่ในเกณฑ์มีประสิทธิภาพ นอกจากนี้ ระบบยังสามารถบ่งชี้ปัญหาการแทรกแซงจากภาษาแม่ของผู้เรียนชาวไทยได้อย่างชัดเจน โดยเฉพาะกลุ่มพยัญชนะม้วนลิ้น (zh, ch, sh, r) และวรรณยุกต์เสียงที่ 3 (Tone 3: 214 และกฎ Tone Sandhi 3+3) ทั้งนี้ ผลการประเมินความพึงพอใจและการใช้งานระบบ (Usability) อยู่ในระดับมากที่สุด

คำสำคัญ: การวิเคราะห์ข้อมูลการเรียนรู้, การฝึกออกเสียงด้วยคอมพิวเตอร์ (CAPT), มาตรฐาน xAPI, อนุกรมวิธานความผิดพลาดทางสัทศาสตร์, ระบบแนะนำบทเรียนซ่อมเสริม, แดชบอร์ดวินิจฉัยการเรียนรู้

Abstract

This cooperative education project aims to design and develop a phonetic Learning Analytics system, an Experience API (xAPI / IEEE 9274.1.1) telemetry pipeline, a learner mastery tracking and adaptive remedial recommendation engine, and diagnostic dashboards for both learners and instructors under a strict Personal Data Protection Act (PDPA) "Zero Audio Storage at Rest" architecture, integrated with the "PakJeen" Mandarin pronunciation training web application (HSK 1–3).

The system implementation consists of four core components executed across a 16-week work plan: (1) formulating eight empirical Learning Questions (LQ1–LQ8) and designing an xAPI telemetry schema backed by a dual-database data warehouse (Turso libSQL and Neon PostgreSQL) protected by a PDPA Consent Gatekeeper; (2) establishing a phonetic Error Taxonomy that categorizes pronunciation errors into four diagnostic states (correct, substitution, omission, and insertion) alongside deterministic pronunciation quality metrics, including Goodness of Pronunciation (GOP), Phoneme Error Rate (PER), and Chao's five-level tone contour scoring; (3) implementing a student mastery and knowledge retention model based on Exponential Moving Average (EMA) and the Ebbinghaus Forgetting Curve, coupled with a rule-based Adaptive Remedial Engine and Student Coach that prescribe targeted vocabulary matching each learner's weak initial consonants and tones; and (4) developing interactive learner dashboards (6-Axis Skill Radar and AI Coach Cards) and a 12-view Instructor Diagnostic Dashboard with built-in psychometric analytics.

Evaluation results across pilot data and a 100-learner evaluation cohort demonstrate 100% schema compliance and zero raw audio persistence. Statistical evaluation of Pre-test and Post-test scores using Paired Sample $t$-test confirms a statistically significant improvement in pronunciation accuracy ($p < .001$) with a large Cohen's $d$ effect size and substantial Hake's Normalized Gain ($\langle g \rangle$). Furthermore, the diagnostic analytics successfully isolate L1 Thai interference patterns, specifically retroflex consonant substitutions (zh, ch, sh, r) and Mandarin Tone 3 contour/sandhi deviations, while user satisfaction and usability evaluations achieved the highest rating level.

Keywords: Learning Analytics, Computer-Assisted Pronunciation Training (CAPT), Experience API (xAPI), Phonetic Error Taxonomy, Adaptive Recommendation Engine, Diagnostic Dashboard

กิตติกรรมประกาศ

รายงานการปฏิบัติงานสหกิจศึกษาฉบับนี้สำเร็จลุล่วงไปได้ด้วยดี ผู้จัดทำขอขอบพระคุณ ศูนย์เทคโนโลยีอิเล็กทรอนิกส์และคอมพิวเตอร์แห่งชาติ (NECTEC) สำนักงานพัฒนาวิทยาศาสตร์และเทคโนโลยีแห่งชาติ (สวทช.) และ สมาคมปัญญาประดิษฐ์ประเทศไทย (Artificial Intelligence Association of Thailand: AIAT) ที่ได้ให้ความอนุเคราะห์รับผู้จัดทำเข้าปฏิบัติงานสหกิจศึกษา ตลอดจนสนับสนุนทรัพยากร เครื่องมือ และสภาพแวดล้อมการวิจัยและพัฒนาเทคโนโลยีปัญญาประดิษฐ์ที่มีคุณภาพสูง

ผู้จัดทำขอกราบขอบพระคุณ คุณภูวิศ เกิดปราโมทย์ หัวหน้าฝ่ายเทคนิคและปัญญาประดิษฐ์ พนักงานที่ปรึกษา ที่ได้สละเวลาอันมีค่าในการถ่ายทอดองค์ความรู้ ให้คำปรึกษา แนะนำแนวทางการออกแบบสถาปัตยกรรมระบบวิเคราะห์ข้อมูลการเรียนรู้ (Learning Analytics) มาตรฐาน xAPI การออกแบบตัววัดทางสัทศาสตร์ และการคุ้มครองข้อมูลส่วนบุคคล (PDPA) ตลอดจนตรวจทานและแก้ไขข้อบกพร่องต่างๆ ด้วยความเอาใจใส่ตลอดระยะเวลา 16 สัปดาห์ของการปฏิบัติงาน

ขอกราบขอบพระคุณคณาจารย์ประจำหลักสูตรวิทยาศาสตรบัณฑิต สาขาวิชาปัญญาประดิษฐ์ คณะวิทยาศาสตร์และเทคโนโลยี มหาวิทยาลัยหัวเฉียวเฉลิมพระเกียรติทุกท่าน ที่ได้ประสิทธิ์ประสาทวิชาความรู้ด้านปัญญาประดิษฐ์ วิทยาการข้อมูล และวิศวกรรมซอฟต์แวร์ อันเป็นรากฐานสำคัญในการนำมาประยุกต์ใช้ในการปฏิบัติงานจริง รวมถึงให้คำแนะนำในการจัดทำรายงานการปฏิบัติงานสหกิจศึกษาฉบับนี้จนมีความสมบูรณ์ตามมาตรฐานวิชาการ

ท้ายที่สุดนี้ ผู้จัดทำขอกราบขอบพระคุณบิดา มารดา และครอบครัว ที่คอยเป็นกำลังใจและให้การสนับสนุนในทุกด้านเสมอมา รวมถึงเพื่อนร่วมงานและเพื่อนนักศึกษาสหกิจศึกษาที่มีส่วนร่วมในการพัฒนาและทดสอบระบบฝึกออกเสียงภาษาจีน "语 ปากจีน" จนโครงงานนี้บรรลุตามวัตถุประสงค์ทุกประการ

1.2 ประวัติองค์กร

ศูนย์เทคโนโลยีอิเล็กทรอนิกส์และคอมพิวเตอร์แห่งชาติ หรือ เนคเทค (NECTEC) ก่อตั้งขึ้นเมื่อวันที่ 16 กันยายน พ.ศ. 2529 โดยมีสถานะเป็นโครงการภายใต้ศูนย์เทคโนโลยีเพื่อการพัฒนา กระทรวงวิทยาศาสตร์ เทคโนโลยีและการพลังงาน เพื่อทำหน้าที่ส่งเสริมและสนับสนุนการวิจัยและพัฒนาเทคโนโลยีด้านอิเล็กทรอนิกส์และคอมพิวเตอร์ของประเทศไทย ต่อมาเมื่อวันที่ 30 ธันวาคม พ.ศ. 2534 ได้มีการประกาศใช้พระราชบัญญัติพัฒนาวิทยาศาสตร์และเทคโนโลยี พ.ศ. 2534 ส่งผลให้มีการจัดตั้งสำนักงานพัฒนาวิทยาศาสตร์และเทคโนโลยีแห่งชาติ (สวทช.) ขึ้น และศูนย์เทคโนโลยีอิเล็กทรอนิกส์และคอมพิวเตอร์แห่งชาติได้เปลี่ยนสถานะเป็นศูนย์แห่งชาติหนึ่งในสังกัดของ สวทช. โดยมีบทบาทหลักในการสร้างฐานรากทางเทคโนโลยีดิจิทัลขั้นสูงให้แก่ประเทศ

ตลอดระยะเวลาการดำเนินงานกว่า 3 ทศวรรษ เนคเทคมีบทบาทสำคัญในการบุกเบิกโครงสร้างพื้นฐานด้านเทคโนโลยีสารสนเทศของประเทศไทย เช่น การพัฒนาเครือข่ายอินเทอร์เน็ตเพื่อการศึกษาและวิจัยในยุคเริ่มต้น การพัฒนาเทคโนโลยีการประมวลผลภาษาธรรมชาติภาษาไทย (Thai Natural Language Processing) เทคโนโลยีการรู้จำและสังเคราะห์เสียงพูด (Speech Recognition and Synthesis) ระบบสมองกลฝังตัว (Embedded Systems) และเทคโนโลยีปัญญาประดิษฐ์ (Artificial Intelligence) ตลอดจนการร่วมมือกับหน่วยงานพันธมิตรทางวิชาการและวิชาชีพ อาทิ สมาคมปัญญาประดิษฐ์ประเทศไทย (AIAT) ในการสร้างระบบนิเวศด้านปัญญาประดิษฐ์และพัฒนากำลังคนด้านเทคโนโลยีดิจิทัลเพื่อขับเคลื่อนเศรษฐกิจและสังคมของประเทศไทยอย่างยั่งยืน

1.3 ลักษณะการประกอบการ

ศูนย์เทคโนโลยีอิเล็กทรอนิกส์และคอมพิวเตอร์แห่งชาติ เป็นองค์กรวิจัยและพัฒนา (Research and Development Organization) ของภาครัฐที่มีภารกิจหลักในการศึกษา ค้นคว้า วิจัย และพัฒนาเทคโนโลยีด้านอิเล็กทรอนิกส์ คอมพิวเตอร์ โทรคมนาคม สารสนเทศ และปัญญาประดิษฐ์ เพื่อนำไปประยุกต์ใช้ในการยกระดับขีดความสามารถในการแข่งขันของภาคอุตสาหกรรม ภาคการศึกษา ภาคการเกษตร ภาคสาธารณสุข และการบริการภาครัฐ โดยแบ่งกลุ่มงานวิจัยและบริการหลักออกเป็น 4 ด้านสำคัญ ได้แก่

  1. ด้านปัญญาประดิษฐ์และวิทยาการข้อมูล (Artificial Intelligence and Data Science): วิจัยและพัฒนาเทคโนโลยีการประมวลผลภาษาธรรมชาติ (NLP) เทคโนโลยีการประมวลผลสัญญาณเสียงและคำพูด (Speech and Audio Processing) คอมพิวเตอร์วิทัศน์ (Computer Vision) และการวิเคราะห์ข้อมูลขนาดใหญ่ (Big Data Analytics) รวมถึงการให้บริการแพลตฟอร์มปัญญาประดิษฐ์แห่งชาติ (เช่น AI FOR THAI)
  2. ด้านระบบไซเบอร์-กายภาพและอินเทอร์เน็ตของสรรพสิ่ง (Cyber-Physical Systems and IoT): วิจัยและพัฒนาเทคโนโลยีเซ็นเซอร์ ระบบสมองกลฝังตัว ระบบอัตโนมัติสำหรับภาคอุตสาหกรรมการผลิต และเทคโนโลยีเกษตรอัจฉริยะ (Smart Farming)
  3. ด้านความมั่นคงปลอดภัยไซเบอร์และโครงสร้างพื้นฐานข้อมูล (Cybersecurity and Data Infrastructure): พัฒนามาตรฐานการแลกเปลี่ยนข้อมูลภาครัฐ สถาปัตยกรรมคลังข้อมูล การคุ้มครองข้อมูลส่วนบุคคล (PDPA Compliance) และการรักษาความมั่นคงปลอดภัยของระบบสารสนเทศ
  4. ด้านการถ่ายทอดเทคโนโลยีและพัฒนากำลังคน (Technology Transfer and Human Resource Development): ถ่ายทอดผลงานวิจัยสู่การใช้ประโยชน์เชิงพาณิชย์และสาธารณประโยชน์ ร่วมกับสถาบันการศึกษาและสมาคมวิชาชีพในการบ่มเพาะนักวิจัยและบุคลากรด้านปัญญาประดิษฐ์ผ่านโครงการสหกิจศึกษาและโครงการวิจัยร่วม

1.4 รูปแบบและการบริหารงานขององค์กร

ศูนย์เทคโนโลยีอิเล็กทรอนิกส์และคอมพิวเตอร์แห่งชาติ มีรูปแบบการบริหารงานแบบองค์กรวิจัยสมัยใหม่ที่มุ่งเน้นผลสัมฤทธิ์เชิงยุทธศาสตร์ (Strategic Research Governance) ภายใต้การกำกับดูแลของสำนักงานพัฒนาวิทยาศาสตร์และเทคโนโลยีแห่งชาติ (สวทช.) โดยมีวิสัยทัศน์ นโยบาย และโครงสร้างองค์กรดังนี้

1.4.1 วิสัยทัศน์

"เป็นองค์กรหลักในการสร้างฐานรากทางเทคโนโลยีอิเล็กทรอนิกส์และสารสนเทศขั้นสูงของประเทศ เพื่อขับเคลื่อนเศรษฐกิจและสังคมดิจิทัลอย่างยั่งยืนด้วยวิทยาศาสตร์ เทคโนโลยี และนวัตกรรม"

1.4.2 นโยบาย

  1. มุ่งเน้นการวิจัยและพัฒนาเทคโนโลยีเชิงลึก (Deep Technology) ด้านอิเล็กทรอนิกส์ คอมพิวเตอร์ และปัญญาประดิษฐ์ ที่ตอบโจทย์ความต้องการของประเทศและสามารถนำไปใช้งานได้จริง
  2. ส่งเสริมการบูรณาการข้อมูลและพัฒนามาตรฐานข้อมูลเปิด (Open Data Standards) ตลอดจนการบริหารจัดการข้อมูลอย่างมีธรรมาภิบาลและสอดคล้องกับกฎหมายคุ้มครองข้อมูลส่วนบุคคล
  3. สร้างเครือข่ายความร่วมมือกับสถาบันการศึกษา หน่วยงานภาครัฐ ภาคเอกชน และสมาคมวิชาชีพด้านปัญญาประดิษฐ์ เพื่อยกระดับทักษะกำลังคนและขยายผลนวัตกรรมสู่วงกว้าง
  4. บริหารจัดการองค์กรด้วยหลักธรรมาภิบาล ความโปร่งใส และการพัฒนาอย่างต่อเนื่อง

1.4.3 โครงสร้างองค์กร

การบริหารงานของศูนย์เทคโนโลยีอิเล็กทรอนิกส์และคอมพิวเตอร์แห่งชาติ อยู่ภายใต้การนำของผู้อำนวยการศูนย์ฯ และรองผู้อำนวยการศูนย์ฯ ที่กำกับดูแลสายงานวิจัยและสายงานสนับสนุนต่างๆ ได้แก่ กลุ่มวิจัยปัญญาประดิษฐ์ (Artificial Intelligence Research Group: AINRG) กลุ่มวิจัยวิทยาการข้อมูลและการวิเคราะห์ กลุ่มวิจัยการสื่อสารและเครือข่าย กลุ่มวิจัยระบบอัตโนมัติและอิเล็กทรอนิกส์ และฝ่ายบริหารจัดการองค์กร ดังแสดงโครงสร้างการบริหารองค์กรในรูปที่ 1.3

รูปที่ 1.3 โครงสร้างการบริหารองค์กรของศูนย์เทคโนโลยีอิเล็กทรอนิกส์และคอมพิวเตอร์แห่งชาติ

1.5 ตำแหน่งและลักษณะงานที่นักศึกษาได้รับมอบหมาย

ในการปฏิบัติงานสหกิจศึกษาครั้งนี้ ผู้จัดทำได้รับมอบหมายให้ปฏิบัติงานในตำแหน่ง นักศึกษาสหกิจศึกษาด้านการวิเคราะห์ข้อมูลการเรียนรู้และวิศวกรรมข้อมูลปัญญาประดิษฐ์ (Learning Analytics & AI Data Engineering Trainee) ภายใต้โครงการวิจัยและพัฒนาแพลตฟอร์มการเรียนรู้ภาษาจีนกลางด้วยปัญญาประดิษฐ์ ("语 ปากจีน") โดยมีลักษณะงานและขอบเขตความรับผิดชอบหลัก 6 ด้าน ตามแผนการดำเนินงาน 16 สัปดาห์ ดังนี้

  1. การกำหนดกรอบการวิเคราะห์การเรียนรู้และคำถามวิจัย (Learning Analytics & Learning Questions): ศึกษากรอบแนวคิด Learning Analytics และงานวิจัยด้านระบบฝึกออกเสียงด้วยคอมพิวเตอร์ (Computer-Assisted Pronunciation Training: CAPT) เพื่อกำหนดคำถามการเรียนรู้เชิงประจักษ์ (Learning Questions: LQ1–LQ8) และตัวชี้วัดทางสัทศาสตร์
  2. การออกแบบมาตรฐานข้อมูล xAPI Telemetry และสถาปัตยกรรมคลังข้อมูลภายใต้กฎหมาย PDPA: ออกแบบโครงสร้างข้อมูลเหตุการณ์การเรียนรู้ตามมาตรฐาน Experience API (xAPI / IEEE 9274.1.1) พัฒนาระบบคัดกรองความยินยอม (PDPA Consent Gatekeeper) ภายใต้หลักการไม่จัดเก็บไฟล์เสียงดิบของผู้เรียน (Zero Audio Storage at Rest) และออกแบบคลังข้อมูลแบบสองชั้น (Dual-Database Data Warehouse) บนฐานข้อมูล Turso (libSQL) และ Neon (PostgreSQL)
  3. การสร้างอนุกรมวิธานความผิดพลาด (Error Taxonomy) และตัววัดคุณภาพการออกเสียง: พัฒนาโมดูลจำแนกความผิดพลาดระดับหน่วยเสียงพยัญชนะต้น (Initials) สระ (Finals) และวรรณยุกต์ (Tones) ออกเป็น 4 สถานะ (correct, substitution, omission, insertion) พร้อมคำนวณตัวชี้วัด Goodness of Pronunciation (GOP), Phoneme Error Rate (PER) และคะแนนรูปร่างวรรณยุกต์ตามมาตรวัด Chao's Pitch Scale (1–5)
  4. การพัฒนาโมเดลผู้เรียน (Mastery / Knowledge Tracing) และระบบแนะนำบทเรียนซ่อมเสริม (Recommendation Engine): พัฒนาอัลกอริทึมคำนวณระดับความเชี่ยวชาญของผู้เรียนด้วยวิธี Exponential Moving Average (EMA) ร่วมกับโมเดลการคงอยู่ของความรู้ตามทฤษฎี Ebbinghaus Forgetting Curve และสร้างระบบ Adaptive Remedial Engine และ Student Coach เพื่อคัดเลือกคำศัพท์ซ่อมเสริมที่ตรงกับจุดอ่อนรายบุคคล
  5. การพัฒนาแดชบอร์ดสำหรับผู้เรียนและผู้สอน (Learner & Instructor Diagnostic Dashboard): ออกแบบและพัฒนาหน้าจอแดชบอร์ดสำหรับผู้เรียน (6-Axis Skill Radar และ AI Coach Recommendations) และแดชบอร์ดวินิจฉัยเชิงลึกสำหรับผู้สอนและผู้ดูแลระบบจำนวน 12 มุมมอง
  6. การประเมินผลสัมฤทธิ์ทางการเรียนและความพึงพอใจ: เก็บข้อมูลนำร่องจากผู้เรียน วิเคราะห์ผลการทดสอบก่อนเรียนและหลังเรียน (Pre-test / Post-test) ด้วยสถิติเชิงอนุมาน (Paired Sample $t$-test, Cohen's $d$, Hake's Normalized Gain) ประเมินความพึงพอใจและการใช้งานระบบ (Usability) ตลอดจนจัดทำคู่มือและส่งมอบระบบ

1.6 พนักงานที่ปรึกษาและตำแหน่งงานหรือแผนกของพนักงานที่ปรึกษา

  • ชื่อ-นามสกุลพนักงานที่ปรึกษา: คุณภูวิศ เกิดปราโมทย์
  • ตำแหน่งงาน: หัวหน้าฝ่ายเทคนิคและปัญญาประดิษฐ์ (Head of Technical and Artificial Intelligence)
  • แผนก / หน่วยงาน: สมาคมปัญญาประดิษฐ์ประเทศไทย (Artificial Intelligence Association of Thailand: AIAT) ปฏิบัติงานร่วมโครงการวิจัยและพัฒนาระบบเทคโนโลยีการศึกษาอัจฉริยะกับศูนย์เทคโนโลยีอิเล็กทรอนิกส์และคอมพิวเตอร์แห่งชาติ (NECTEC)

1.7 ระยะเวลาที่ปฏิบัติงาน

ผู้จัดทำได้เข้าปฏิบัติงานสหกิจศึกษาตั้งแต่วันที่ 4 มิถุนายน พ.ศ. 2569 ถึง วันที่ 20 พฤศจิกายน พ.ศ. 2569 รวมระยะเวลาทั้งสิ้น 16 สัปดาห์ (คิดเป็นจำนวนวันปฏิบัติงานรวม 122 วันทำการ หรือ 976 ชั่วโมงปฏิบัติงาน) โดยปฏิบัติงานในวันจันทร์ถึงวันศุกร์ เวลา 08.30 น. ถึง 17.30 น.

ในบทนี้จะกล่าวถึงภาพรวมของโครงงานสหกิจศึกษา ซึ่งประกอบด้วย ความเป็นมาและความสำคัญของปัญหา วัตถุประสงค์ของโครงงานสหกิจศึกษา ขอบเขตของโครงงานสหกิจศึกษา ประโยชน์ที่คาดว่าจะได้รับ ขั้นตอนและวิธีการดำเนินงาน ตลอดจนอุปกรณ์และเครื่องมือที่ใช้ในการพัฒนาระบบวิเคราะห์ข้อมูลการเรียนรู้และแดชบอร์ดวินิจฉัยการออกเสียงภาษาจีนเชิงสัทศาสตร์ โดยมีรายละเอียดดังต่อไปนี้

2.1 ความเป็นมาและความสำคัญของปัญหา

ภาษาจีนกลาง (Mandarin Chinese) เป็นภาษาที่มีความสำคัญอย่างยิ่งต่อเศรษฐกิจ การค้า การท่องเที่ยว และความร่วมมือทางเทคโนโลยีในระดับสากล ส่งผลให้ความต้องการเรียนรู้ภาษาจีนของนักเรียน นักศึกษา และบุคลากรชาวไทยเพิ่มสูงขึ้นอย่างต่อเนื่อง อย่างไรก็ตาม อุปสรรคสำคัญที่สุดของผู้เรียนชาวไทยในการฝึกฝนทักษะการพูดภาษาจีนกลางตามมาตรฐานการสอบวัดระดับความรู้ภาษาจีน (Hanyu Shuiping Kaoshi: HSK ระดับ 1–3) คือความแตกต่างทางระบบสัทศาสตร์ระหว่างภาษาไทยและภาษาจีนกลาง (L1 Interference) โดยเฉพาะกลุ่มพยัญชนะต้นม้วนลิ้น (Retroflex Initials: zh, ch, sh, r) ที่ผู้เรียนชาวไทยมักออกเสียงสับสนกับพยัญชนะปลายลิ้น (z, c, s) รวมถึงการควบคุมความถี่มูลฐานของเสียง ($F_0$) ในระบบวรรณยุกต์ภาษาจีนกลาง 4 เสียง และกฎการเปลี่ยนเสียงวรรณยุกต์ (Tone Sandhi) เช่น เสียงที่ 3 ซ้อนกัน (3+3 $\rightarrow$ 2+3) ซึ่งในปัจจุบันได้มีการนำเทคโนโลยีการฝึกออกเสียงด้วยคอมพิวเตอร์ (Computer-Assisted Pronunciation Training: CAPT) เข้ามาช่วยตรวจจับความถี่เสียงและให้คะแนนเบื้องต้นแก่ผู้เรียนผ่านเว็บแอปพลิเคชัน

แม้ว่าแอปพลิเคชันฝึกออกเสียงทั่วไปจะสามารถแสดงคะแนนการออกเสียงในแต่ละครั้งแบบเฉพาะหน้า (Immediate Feedback) ได้ แต่ระบบส่วนใหญ่ยังคงขาดสถาปัตยกรรมการวิเคราะห์ข้อมูลการเรียนรู้ (Learning Analytics) เชิงลึกที่สามารถรวบรวมพฤติกรรมการเรียนรู้และร่องรอยความผิดพลาดทางสัทศาสตร์ในระยะยาวได้อย่างเป็นระบบ ส่งผลให้เกิดปัญหาสำคัญ 3 ประการ ประการแรกคือ การขาดอนุกรมวิธานความผิดพลาด (Error Taxonomy) และตัววัดคุณภาพการออกเสียงระดับหน่วยเสียงที่ได้มาตรฐาน ทำให้ไม่สามารถจำแนกได้ว่าคะแนนที่ต่ำเกิดจากการออกเสียงแทนที่ (Substitution) การตกหล่นของเสียง (Omission) หรือการแทรกเสียงเกิน (Insertion) ส่งผลให้ระบบไม่สามารถติดตามระดับความเชี่ยวชาญที่แท้จริง (Mastery & Knowledge Tracing) หรือแนะนำบทเรียนซ่อมเสริมที่ตรงจุดอ่อนรายบุคคลได้ ประการที่สองคือ ผู้สอนและผู้ดูแลหลักสูตรขาดเครื่องมือแดชบอร์ดวินิจฉัยระดับกลุ่มเรียน (Cohort Diagnostic Dashboard) ที่เชื่อมโยงข้อมูลตามมาตรฐานสากล Experience API (xAPI) เพื่อใช้ตอบคำถามวิจัยด้านการเรียนรู้หรือประเมินผลสัมฤทธิ์ก่อนและหลังเรียน (Pre-test / Post-test) เชิงสถิติ และประการที่สามคือ ความเสี่ยงด้านกฎหมายคุ้มครองข้อมูลส่วนบุคคล (PDPA) เนื่องจากข้อมูลเสียงพูดของมนุษย์ถือเป็นข้อมูลชีวมิติ (Biometric/Voiceprint Data) ที่สามารถระบุตัวตนได้ การจัดเก็บไฟล์เสียงดิบของผู้เรียนไว้บนเซิร์ฟเวอร์โดยไม่มีการควบคุมความยินยอมที่รัดกุมย่อมก่อให้เกิดความเสี่ยงด้านความเป็นส่วนตัวและความมั่นคงปลอดภัยของข้อมูล

ด้วยเหตุนี้ ผู้จัดทำจึงได้ออกแบบและพัฒนาระบบวิเคราะห์ข้อมูลการเรียนรู้และแดชบอร์ดวินิจฉัยการออกเสียงภาษาจีนเชิงสัทศาสตร์ตามมาตรฐาน xAPI ภายใต้การคุ้มครองข้อมูลส่วนบุคคล โดยบูรณาการเข้ากับแพลตฟอร์มเว็บแอปพลิเคชันฝึกออกเสียงภาษาจีน "语 ปากจีน" แนวคิดหลักของโครงงานนี้คือการกำหนดคำถามการเรียนรู้เชิงประจักษ์ (Learning Questions: LQ1–LQ8) และการออกแบบท่อส่งข้อมูลพฤติกรรมการเรียนรู้ตามมาตรฐาน IEEE 9274.1.1 (xAPI) ที่ทำงานร่วมกับสถาปัตยกรรมคลังข้อมูลแบบสองชั้น (Dual-Database Data Warehouse: Turso libSQL และ Neon PostgreSQL) ภายใต้หลักการไม่จัดเก็บไฟล์เสียงดิบลงฐานข้อมูลถาวร (PDPA Zero Audio Storage at Rest) โดยระบบจะสกัดเฉพาะคุณลักษณะเชิงตัวเลขและอนุกรมวิธานความผิดพลาดทางสัทศาสตร์ ได้แก่ คะแนน Goodness of Pronunciation (GOP) อัตราความผิดพลาด Phoneme Error Rate (PER) และคะแนนรูปร่างวรรณยุกต์ตามมาตรวัด Chao's Pitch Scale (1–5) เพื่อนำมาประมวลผลด้วยโมเดลติดตามความเชี่ยวชาญแบบค่าเฉลี่ยเคลื่อนที่เอ็กซ์โพเนนเชียล (Exponential Moving Average: EMA) ร่วมกับทฤษฎีเส้นโค้งการลืมของเอ็บบิงเฮาส์ (Ebbinghaus Forgetting Curve) และส่งต่อไปยังระบบแนะนำบทเรียนซ่อมเสริมอัตโนมัติ (Adaptive Remedial & Student Coach Engine) ตลอดจนแสดงผลผ่านแดชบอร์ดวินิจฉัยสำหรับผู้เรียนและผู้สอน ซึ่งช่วยให้ผู้เรียนสามารถแก้ไขจุดบกพร่องทางสัทศาสตร์ของตนเองได้อย่างตรงจุด และช่วยให้ผู้สอนสามารถประเมินผลสัมฤทธิ์ทางการเรียนด้วยสถิติเชิงอนุมานได้อย่างแม่นยำและปลอดภัยสูงสุด

2.2 วัตถุประสงค์ของโครงงานสหกิจศึกษา

  1. เพื่อศึกษากรอบการวิเคราะห์ข้อมูลการเรียนรู้ (Learning Analytics) กำหนดคำถามการเรียนรู้เชิงประจักษ์ (Learning Questions: LQ1–LQ8) และออกแบบโครงสร้างข้อมูลเหตุการณ์การเรียนรู้ตามมาตรฐาน xAPI (IEEE 9274.1.1) ร่วมกับคลังข้อมูลภายใต้มาตรการคุ้มครองข้อมูลส่วนบุคคล (PDPA Zero Audio Storage)
  2. เพื่อสร้างอนุกรมวิธานความผิดพลาดทางสัทศาสตร์ (Error Taxonomy) และพัฒนาโมดูลคำนวณตัววัดคุณภาพการออกเสียงระดับหน่วยเสียงและวรรณยุกต์ ได้แก่ คะแนนความแม่นยำของหน่วยเสียง (GOP) อัตราความผิดพลาดของหน่วยเสียง (PER) และคะแนนรูปร่างวรรณยุกต์ (Tone Contour Score)
  3. เพื่อพัฒนาโมเดลติดตามความเชี่ยวชาญและการคงอยู่ของความรู้ของผู้เรียน (Mastery & Knowledge Tracing Model) ร่วมกับระบบแนะนำคำศัพท์และบทเรียนซ่อมเสริมรายบุคคลอัตโนมัติ (Adaptive Remedial & Student Coach Engine)
  4. เพื่อพัฒนาแดชบอร์ดวินิจฉัยผลการเรียนรู้สำหรับผู้เรียนและผู้สอน (Learner & Instructor Diagnostic Dashboard) และประเมินผลสัมฤทธิ์ทางการเรียน (Pre-test / Post-test) ตลอดจนความพึงพอใจและการใช้งานระบบ (Usability)

2.3 ขอบเขตของโครงงานสหกิจศึกษา

ในการดำเนินโครงงานสหกิจศึกษาครั้งนี้ ผู้จัดทำได้กำหนดขอบเขตของการพัฒนาระบบออกเป็น 5 ด้านหลัก ตามแผนการปฏิบัติงาน 16 สัปดาห์ ดังนี้

  1. ขอบเขตด้านกรอบคำถามการเรียนรู้ (Learning Questions & Metrics):
  • กำหนดคำถามการเรียนรู้ (LQ1–LQ8) ครอบคลุมการวิเคราะห์หน่วยเสียงพยัญชนะต้นและสระที่เป็นปัญหาของผู้เรียนชาวไทย การวิเคราะห์ความสับสนของวรรณยุกต์ 4 เสียงและกฎ Tone Sandhi ผลกระทบของพฤติกรรมการกดฟังเสียงตัวอย่างก่อนพูด (Listening Behavior Impact) จุดติดขัดและการเลิกเรียนกลางคันในด่านเควสต์ (Drop-off Funnel) ความสัมพันธ์ระหว่างทักษะทั้ง 6 มิติ และการวัดพัฒนาการก่อนและหลังเรียน
  1. ขอบเขตด้านระบบเก็บข้อมูล xAPI Telemetry คลังข้อมูล และการคุ้มครองข้อมูลส่วนบุคคล (PDPA):
  • พัฒนาระบบคัดกรองความยินยอม (PDPA Consent Gatekeeper) ที่บังคับตรวจสอบสถานะความยินยอม (consent_status = 'consented') ก่อนบันทึกข้อมูลการเรียนรู้ พร้อมรองรับสิทธิในการถอนความยินยอมและลบข้อมูล (Right to Withdraw & Erasure)
  • ใช้สถาปัตยกรรม Zero Audio Storage at Rest โดยประมวลผลสัญญาณเสียงเฉพาะในหน่วยความจำชั่วคราว และส่งเฉพาะข้อมูลตัวเลขเชิงสัทศาสตร์และรหัสเหตุการณ์เข้าสู่ระบบ
  • แปลงข้อมูลพฤติกรรมการเรียนรู้และการประเมินเสียงให้อยู่ในรูปแบบมาตรฐาน xAPI Statement (Actor, Verb, Object, Result, Context) และจัดเก็บลงในคลังข้อมูลแบบสองชั้น ได้แก่ ฐานข้อมูลหลัก Turso (libSQL / Edge SQLite) และฐานข้อมูลวิเคราะห์ข้อมูล Neon (Serverless PostgreSQL)
  1. ขอบเขตด้านอนุกรมวิธานความผิดพลาด (Error Taxonomy) และตัววัดคุณภาพการออกเสียง:
  • แยกวิเคราะห์พยางค์พินอินออกเป็นพยัญชนะต้น (Initials/Shengmu 23 เสียง) และสระพร้อมวรรณยุกต์ (Finals+Tones/Yunmu+Shengtiao)
  • จำแนกสถานะความผิดพลาดระดับหน่วยเสียงออกเป็น 4 ประเภท ได้แก่ ออกเสียงถูกต้อง (correct) ออกเสียงแทนที่/สับสน (substitution) เสียงตกหล่น (omission) และมีเสียงแทรกเกิน (insertion)
  • คำนวณตัววัดคุณภาพการออกเสียงเชิงกำหนด (Deterministic Metrics) ได้แก่ คะแนนความชัดเจนจากอัลกอริทึม YIN (Clarity Score) คะแนนรูปร่างความถี่เสียงบนมาตรวัด Chao Scale 1–5 ความชันของเสียง (Slope) คะแนน Goodness of Pronunciation (GOP 0–100) และอัตราความผิดพลาด Phoneme Error Rate (PER 0.0–1.0)
  1. ขอบเขตด้านโมเดลผู้เรียน (Mastery Model) และระบบแนะนำบทเรียนซ่อมเสริม (Recommendation Engine):
  • คำนวณคะแนนความเชี่ยวชาญสะสม (EMA Mastery Score) ด้วยปัจจัยการปรับเรียบ $\alpha = 0.30$ ร่วมกับการคำนวณอัตราการคงอยู่ของความจำตามสมการ $R(t) = e^{-\Delta t / S}$ ของเอ็บบิงเฮาส์
  • พัฒนา Adaptive Remedial Engine และ Student Coach Engine เพื่อคัดเลือกคำศัพท์ซ่อมเสริมสูงสุด 6 คำ และสร้างคำแนะนำลำดับความสำคัญ (High, Medium, Low Priority) จากหน่วยเสียงพยัญชนะม้วนลิ้น (zh, ch, sh, r) วรรณยุกต์ที่อ่อน และทักษะที่ยังขาดความสมดุล
  1. ขอบเขตด้านแดชบอร์ดผู้เรียน ผู้สอน และการประเมินผล:
  • แดชบอร์ดผู้เรียน (/analytics): แสดงแผนภูมิเรดาร์ทักษะ 6 มิติ (6-Axis Skill Radar: ความชัดสัทศาสตร์ GOP, วรรณยุกต์ 4 เสียง, คัดอักษรจีน, บทสนทนา AI, ความจำคำศัพท์, และด่านการเรียนรู้) การ์ดคำแนะนำจาก AI Coach การ์ดคำศัพท์ซ่อมเสริมพร้อมคู่มือการจัดวางอวัยวะออกเสียง (Articulation Guides) และประวัติความก้าวหน้า
  • แดชบอร์ดผู้สอนและผู้ดูแลระบบ (/admin): ประกอบด้วยมุมมองการวิเคราะห์ 12 มุมมอง ได้แก่ ภาพรวมระบบ, วินิจฉัยการออกเสียง, คัดอักษรจีน, ความคล่องแคล่วบทสนทนา, การจำคำศัพท์, จุดติดขัดด่านเควสต์, คำศัพท์ที่ยากที่สุด, ผลสอบ HSK Mock Exam, วิเคราะห์พัฒนาการ Pre/Post-test, จัดการผู้ใช้และข้อมูล 360 องศา (Learner 360 Profile), จัดการเนื้อหาด่าน และประวัติความยินยอม PDPA พร้อมระบบส่งออกข้อมูลวิจัย (CSV / JSONL Export)
  • การประเมินผล: วิเคราะห์ข้อมูลผู้เรียนด้วยสถิติ Paired Sample $t$-test, ค่า $p$-value, ขนาดอิทธิพล Cohen's $d$, ช่วงความเชื่อมั่น 95% (95% CI) และค่าพัฒนาการสัมพัทธ์ Hake's Normalized Gain ($\langle g \rangle$)

2.4 ประโยชน์ที่คาดว่าจะได้รับ

  1. ได้ระบบวิเคราะห์ข้อมูลการเรียนรู้และคลังข้อมูลตามมาตรฐานสากล xAPI (IEEE 9274.1.1) ที่ปฏิบัติตามพระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล (PDPA) อย่างเคร่งครัดด้วยสถาปัตยกรรม Zero Audio Storage at Rest
  2. ผู้เรียนชาวไทยสามารถทราบจุดบกพร่องทางสัทศาสตร์ของตนเองในระดับหน่วยเสียงพยัญชนะต้น สระ และวรรณยุกต์ พร้อมได้รับคำศัพท์ซ่อมเสริมและคำแนะนำการจัดวางลิ้นและริมฝีปากที่ตรงกับปัญหาเฉพาะบุคคล
  3. ผู้สอนและนักวิจัยด้านเทคโนโลยีการศึกษาสามารถใช้แดชบอร์ดวินิจฉัยระดับกลุ่มเรียน (Cohort Analytics) ในการติดตามพัฒนาการของผู้เรียน ตรวจสอบจุดติดขัดของบทเรียน และวิเคราะห์ผลสัมฤทธิ์ Pre-test / Post-test เชิงสถิติได้ทันทีโดยไม่ต้องคำนวณด้วยโปรแกรมภายนอก
  4. เป็นต้นแบบสถาปัตยกรรมวิศวกรรมข้อมูลการเรียนรู้ (Educational Data Engineering) และระบบแนะนำบทเรียนปรับเหมาะ (Adaptive Learning System) สำหรับศูนย์เทคโนโลยีอิเล็กทรอนิกส์และคอมพิวเตอร์แห่งชาติ (NECTEC) และสมาคมปัญญาประดิษฐ์ประเทศไทย (AIAT) ในการขยายผลสู่แพลตฟอร์มการเรียนรู้ภาษาต่างประเทศอื่นต่อไป

2.5 ขั้นตอนและวิธีการดำเนินงาน

ในการพัฒนาระบบวิเคราะห์ข้อมูลการเรียนรู้และแดชบอร์ดวินิจฉัยการออกเสียงภาษาจีนเชิงสัทศาสตร์ ผู้จัดทำได้ประยุกต์ใช้วงจรการพัฒนาระบบซอฟต์แวร์และวิทยาการข้อมูล 7 ขั้นตอน ตลอดระยะเวลา 16 สัปดาห์ (วันที่ 4 มิถุนายน พ.ศ. 2569 ถึง วันที่ 20 พฤศจิกายน พ.ศ. 2569) ดังนี้

  1. การวางแผนและกำหนดกรอบคำถามการเรียนรู้ (Planning & Learning Questions Formulation): ศึกษาโครงสร้างองค์กร ระบบงานของแอปพลิเคชัน "语 ปากจีน" ทบทวนวรรณกรรมด้าน Learning Analytics และ CAPT พร้อมกำหนดคำถามการเรียนรู้ LQ1–LQ8 และตัวชี้วัดทางสัทศาสตร์
  2. การวิเคราะห์ระบบและข้อกำหนดด้านจริยธรรมข้อมูล (System Analysis & PDPA Compliance Spike): ทดสอบท่อส่งข้อมูลการวิเคราะห์เสียง (Audio Pipeline Spike) วิเคราะห์มาตรฐาน xAPI (IEEE 9274.1.1) และกำหนดมาตรการคุ้มครองข้อมูลส่วนบุคคล PDPA Zero Audio Storage
  3. การออกแบบสถาปัตยกรรมข้อมูลและระบบงาน (Data Schema & System Design): ออกแบบโครงสร้าง xAPI Event Schema พจนานุกรมฐานข้อมูลบน Turso (libSQL) และ Neon (PostgreSQL) ออกแบบอนุกรมวิธานความผิดพลาด (Error Taxonomy) และออกแบบส่วนติดต่อผู้ใช้ของแดชบอร์ดผู้เรียนและผู้สอน
  4. การพัฒนาระบบเก็บข้อมูลและตัววัดคุณภาพเสียง (Telemetry & Phonetic Metrics Implementation): พัฒนาส่วนดักจับเหตุการณ์การเรียนรู้ในแอปฝึกพูด (src/lib/telemetry/adapter.ts, src/lib/xapi.ts) ระบบ Consent Gatekeeper และโมดูลคำนวณคะแนน GOP, PER, YIN Clarity และ Chao's Pitch Scale
  5. การเก็บข้อมูลนำร่องและพัฒนาโมเดลผู้เรียน (Pilot Data Collection, Mastery & Recommendation Engine): เริ่มเก็บข้อมูลการใช้งานนำร่องจากผู้เรียนจริง ควบคู่กับการพัฒนาโมเดลติดตามความเชี่ยวชาญ (EMA Mastery & Ebbinghaus Retention) ระบบแนะนำคำศัพท์ซ่อมเสริม (remedialEngine.ts, studentCoachEngine.ts) และแดชบอร์ดผู้เรียน/ผู้สอน
  6. การประเมินผล วิเคราะห์ผล และปรับปรุงระบบ (Evaluation, Statistical Analysis & Optimization): ประมวลผลคะแนนทดสอบก่อนและหลังเรียน (Pre-test / Post-test) ด้วยเครื่องมือสถิติ (statisticalEngine.ts) ประเมินความพึงพอใจและการใช้งานระบบ (Usability) และปรับปรุงประสิทธิภาพของระบบ
  7. การติดตั้ง ส่งมอบงาน และจัดทำรายงาน (Deployment, Documentation & Handover): ติดตั้งระบบขึ้นสู่สภาพแวดล้อมใช้งานจริง (Production Deployment) จัดทำคู่มือการใช้งาน รายงานสหกิจศึกษาฉบับสมบูรณ์ โปสเตอร์ และนำเสนอผลงาน

3.1.1 กรอบการวิเคราะห์ข้อมูลการเรียนรู้ (Learning Analytics) และระบบฝึกออกเสียงด้วยคอมพิวเตอร์ (CAPT)

การวิเคราะห์ข้อมูลการเรียนรู้ (Learning Analytics: LA) ตามคำนิยามของสมาคมวิจัยการวิเคราะห์การเรียนรู้ (Society for Learning Analytics Research: SoLAR) คือ การวัด การเก็บรวบรวม การวิเคราะห์ และการรายงานข้อมูลเกี่ยวกับผู้เรียนและบริบทของการเรียนรู้ โดยมีจุดมุ่งหมายเพื่อทำความเข้าใจและปรับปรุงกระบวนการเรียนรู้ตลอดจนสภาพแวดล้อมที่การเรียนรู้นั้นเกิดขึ้นให้มีประสิทธิภาพสูงสุด วงจรการทำงานของระบบ Learning Analytics ตามแนวคิดของ Clow (2012) [1] ประกอบด้วย 4 ขั้นตอนที่หมุนเวียนต่อเนื่องกันเป็นวงจรปิด (Closed-Loop Learning Analytics Cycle) ดังแสดงในรูปที่ 3.1 ได้แก่

  1. ผู้เรียน (Learners): ผู้เรียนทำกิจกรรมการเรียนรู้ เช่น การฝึกออกเสียงคำศัพท์ การทำแบบฝึกหัดในด่านเควสต์ หรือการทำแบบทดสอบวัดระดับ
  2. ข้อมูล (Data): ระบบดักจับร่องรอยพฤติกรรมการเรียนรู้ (Digital Traces) เช่น จำนวนครั้งที่กดฟังเสียงตัวอย่าง เวลาที่ใช้คิดก่อนพูด (Hesitation Latency) และค่าพารามิเตอร์ทางสัทศาสตร์
  3. ตัวชี้วัดและการวิเคราะห์ (Metrics & Analytics): การนำข้อมูลดิบมาประมวลผลด้วยอัลกอริทึมทางสถิติและปัญญาประดิษฐ์เพื่อสร้างตัวชี้วัดความเชี่ยวชาญ อนุกรมวิธานความผิดพลาด และแผนภูมิภาพ (Visualization)
  4. การแทรกแซงและป้อนกลับ (Interventions): การนำผลการวิเคราะห์กลับไปช่วยเหลือผู้เรียน เช่น การแนะนำคำศัพท์ซ่อมเสริมรายบุคคล หรือการแจ้งเตือนผู้สอนให้ทราบถึงผู้เรียนที่ต้องการความช่วยเหลือพิเศษ

รูปที่ 3.1 แผนภาพวงจรการวิเคราะห์ข้อมูลการเรียนรู้ (Learning Analytics Cycle) ที่ประยุกต์ใช้ในโครงงาน

เมื่อนำกรอบแนวคิด Learning Analytics มาบูรณาการเข้ากับระบบฝึกออกเสียงด้วยคอมพิวเตอร์ (Computer-Assisted Pronunciation Training: CAPT) จะช่วยยกระดับระบบ CAPT จากเดิมที่ทำหน้าที่เพียงตรวจจับความถี่มูลฐานของเสียง ($F_0$) ด้วยอัลกอริทึมการหาค่าสหสัมพันธ์ในตัวเองเชิงอนุพันธ์ (YIN Pitch Tracking Algorithm) [2] แล้วแจ้งผลว่า "ผ่าน" หรือ "ไม่ผ่าน" ไปสู่ระบบวินิจฉัยเชิงสัทศาสตร์ที่สามารถตอบคำถามวิจัยด้านการเรียนรู้ (Learning Questions) ได้อย่างรอบด้าน ทั้งในระดับรายบุคคลและระดับกลุ่มผู้เรียน

3.1.2 สัทศาสตร์ภาษาจีนกลาง อนุกรมวิธานความผิดพลาด (Error Taxonomy) และตัววัดคุณภาพการออกเสียง

โครงสร้างพยางค์ในภาษาจีนกลางมาตรฐาน (Standard Mandarin / Putonghua) ประกอบด้วย 3 องค์ประกอบหลัก ได้แก่ พยัญชนะต้น (Initials / 声母 Shēngmǔ จำนวน 21 เสียงและพยัญชนะกึ่งสระ y, w) สระเดี่ยวหรือสระประสม (Finals / 韵母 Yùnmǔ) และวรรณยุกต์ (Tones / 声调 Shēngdiào จำนวน 4 เสียงหลัก และเสียงเบา 1 เสียง) ในทางสัทศาสตร์กลศาสตร์เสียง จ้าว หยวนเริ่น (Yuen Ren Chao) [3] ได้กำหนดมาตรวัดระดับเสียงวรรณยุกต์ภาษาจีนกลางออกเป็น 5 ระดับ (Chao's Five-Level Tone Letters) ตั้งแต่ระดับ 1 (ต่ำสุด) ถึงระดับ 5 (สูงสุด) โดยสามารถแปลงค่าความถี่มูลฐาน $F_0$ (หน่วยเป็นเฮิรตซ์: Hz) ของผู้พูดแต่ละคนให้อยู่ในมาตรวัดลอการิทึม 1–5 เพื่อขจัดความแตกต่างของช่วงเสียงระหว่างเพศชายและเพศหญิง ดังสมการที่ (3.1)

$$\text{Chao}(t) = 1 + 4 \times \frac{\log_{10}(F_0(t)) - \log_{10}(F_{0,\min})}{\log_{10}(F_{0,\max}) - \log_{10}(F_{0,\min})}$$

โดยลักษณะรูปร่างระดับเสียงของวรรณยุกต์ภาษาจีนกลางทั้ง 4 เสียงหลักและเสียงเบาตามมาตรวัดของจ้าว หยวนเริ่น สามารถสรุปได้ดังแสดงในตารางที่ 3.1

ตารางที่ 3.1 ระบบวรรณยุกต์ภาษาจีนกลางตามมาตรวัดระดับเสียงของจ้าว หยวนเริ่น (Chao's Pitch Scale 1–5)

วรรณยุกต์ชื่อภาษาจีนสัญลักษณ์พินอินค่าตัวเลขระดับเสียง (Chao Scale)ลักษณะรูปร่างความถี่เสียง (Pitch Contour)ตัวอย่างคำศัพท์
เสียงที่ 1阴平 (Yīnpíng)ā55เสียงสูงคงที่ตลอดพยางค์ (High Level)妈 (mā - แม่)
เสียงที่ 2阳平 (Yángpíng)á35เสียงไต่ระดับจากกลางขึ้นสูง (High Rising)麻 (má - ป่าน)
เสียงที่ 3上声 (Shǎngshēng)ǎ214 (หรือ 21)เสียงกดต่ำลงแล้วตวัดขึ้น (Low Dipping)马 (mǎ - ม้า)

เสียงเบา轻声 (Qīngshēng)a0 (แปรผัน)เสียงสั้นและเบา ความสูงขึ้นอยู่กับพยางค์หน้า (Neutral)吗 (ma - ไหม)

นอกจากนี้ ภาษาจีนกลางยังมีกฎการแปรเสียงวรรณยุกต์ตามบริบทพยางค์ข้างเคียง (Tone Sandhi) ที่สำคัญที่สุดคือ กฎวรรณยุกต์เสียงที่ 3 ซ้อนกัน (Third-Tone Sandhi: 3+3 $\rightarrow$ 2+3) เช่น คำว่า 你好 (nǐ hǎo) ซึ่งพยางค์แรกมีวรรณยุกต์พื้นเดิม (Underlying Tone) เป็นเสียงที่ 3 แต่เมื่อออกเสียงจริงต้องแปรเป็นวรรณยุกต์พื้นผิว (Surface Tone) เสียงที่ 2 (ní hǎo) รวมถึงกฎการเปลี่ยนเสียงของคำว่า 不 (bù $\rightarrow$ bú เมื่อตามด้วยเสียงที่ 4) และ 一 (yī $\rightarrow$ yí หรือ yì)

เพื่อวัดคุณภาพการออกเสียงและจำแนกข้อผิดพลาดของผู้เรียนชาวไทยอย่างเป็นระบบ โครงงานนี้ได้ประยุกต์ใช้อนุกรมวิธานความผิดพลาดระดับหน่วยเสียง (Phoneme-level Error Taxonomy) และตัววัดมาตรฐาน 2 ตัวชี้วัดหลัก [4] ได้แก่

  1. คะแนนความแม่นยำในการออกเสียง (Goodness of Pronunciation: GOP): ในระบบรู้จำเสียงพูดแบบดั้งเดิมของ Witt และ Young (2000) [4] ค่า GOP คำนวณจากอัตราส่วนความน่าจะเป็นแบบลอการิทึม (Log-Likelihood Ratio) ของหน่วยเสียงเป้าหมาย $p$ ต่อหน่วยเสียงที่มีความน่าจะเป็นสูงสุด ในโครงงานนี้ได้ปรับปรุงสมการ GOP สำหรับประมวลผลแบบกำหนดค่าแน่นอน (Deterministic Acoustic GOP) โดยถ่วงน้ำหนักระหว่างความชัดเจนของสัญญาณคาบเวลาจากอัลกอริทึม YIN ($S_{\text{clarity}}$) ความแม่นยำของรูปร่างวรรณยุกต์และค่าความชัน ($S_{\text{contour}}$) และความแม่นยำของหน่วยเสียงพยัญชนะ/สระ ($S_{\text{segment}}$) ให้อยู่ในช่วงคะแนน 0 ถึง 100 คะแนน ดังสมการที่ (3.2)

$$\text{GOP}_i = \text{ clamp}_{[0, 100]} \left( w_1 S_{\text{segment}, i} + w_2 S_{\text{contour}, i} + w_3 S_{\text{clarity}, i} \right)$$

  1. อัตราความผิดพลาดของหน่วยเสียง (Phoneme Error Rate: PER): คำนวณจากระยะห่างการแก้ไขแบบเลเวนชไตน์ (Levenshtein Edit Distance) ระหว่างลำดับหน่วยเสียงเป้าหมายและลำดับหน่วยเสียงที่ระบบตรวจจับได้ โดยจำแนกความคลาดเคลื่อนออกเป็น 3 ประเภทในอนุกรมวิธานความผิดพลาด ได้แก่ การออกเสียงแทนที่หรือสับสน ($S$: Substitution เช่น เป้าหมายคือพยัญชนะม้วนลิ้น zh แต่ออกเสียงเป็น z) การตกหล่นหรือไม่ได้ออกเสียง ($D$: Omission/Deletion) และการแทรกเสียงเกิน ($I$: Insertion) เทียบกับจำนวนหน่วยเสียงเป้าหมายทั้งหมด ($N$) ดังสมการที่ (3.3)

$$\text{PER} = \frac{S + D + I}{N}$$

3.1.3 มาตรฐานข้อมูลกิจกรรมการเรียนรู้ xAPI (IEEE 9274.1.1) และการคุ้มครองข้อมูลส่วนบุคคล (PDPA)

มาตรฐาน Experience API (xAPI หรือชื่อเดิมคือ Tin Can API) ซึ่งได้รับการรับรองเป็นมาตรฐานสากล IEEE 9274.1.1 [5] เป็นสถาปัตยกรรมข้อมูลสำหรับการแลกเปลี่ยนและจัดเก็บประวัติกิจกรรมการเรียนรู้ในคลังระเบียนการเรียนรู้ (Learning Record Store: LRS) โดยข้อมูลทุกเหตุการณ์จะถูกจัดอยู่ในรูปแบบประโยคโครงสร้าง JSON ที่เรียกว่า xAPI Statement ซึ่งประกอบด้วยองค์ประกอบหลัก 3 ส่วน คือ "ใคร (Actor) ทำกริยาอะไร (Verb) กับวัตถุการเรียนรู้ใด (Object)" และขยายความด้วยผลลัพธ์ (Result) และบริบท (Context) ดังนี้

  • Actor: ข้อมูลระบุตัวตนผู้เรียนที่ผ่านการแฝงชื่อ (Pseudonymized User Account / UUID)
  • Verb: รหัส URI มาตรฐานของกริยาการเรียนรู้ เช่น http://adlnet.gov/expapi/verbs/experienced (การกดฟังเสียงตัวอย่าง) http://adlnet.gov/expapi/verbs/attempted (การพยายามออกเสียงพยางค์) และ http://adlnet.gov/expapi/verbs/scored (การประเมินผลคะแนนคำศัพท์)
  • Object: ข้อมูลคำศัพท์หรือด่านการเรียนรู้ เช่น รหัสคำศัพท์ ตัวอักษรจีน (Hanzi) พินอิน และระดับ HSK
  • Result: คะแนนที่ได้ (scaled, raw, min, max) สถานะการผ่านเกณฑ์ (success, completion) และส่วนขยาย (extensions) ที่บรรจุรายละเอียดคะแนน GOP, PER, ความถี่ $F_0$ เฉลี่ย และรายการอนุกรมวิธานความผิดพลาดระดับหน่วยเสียง
  • Context: ข้อมูลบริบทแวดล้อม เช่น โหมดการฝึก (stage, word, assessment) จำนวนครั้งที่กดฟังเสียงตัวอย่างก่อนพูด และเวลาความลังเลก่อนเริ่มพูด (Hesitation Latency)

ในด้านจริยธรรมข้อมูลและการปฏิบัติตามพระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (Personal Data Protection Act: PDPA) และระเบียบ GDPR ของสหภาพยุโรป ข้อมูลไฟล์เสียงพูดดิบ (Raw Audio Waveform) ของผู้เรียนถือเป็นข้อมูลส่วนบุคคลที่มีความอ่อนไหวเนื่องจากสามารถนำไปสกัดอัตลักษณ์บุคคลจากเสียง (Voice Biometrics) ได้ โครงงานนี้จึงได้ออกแบบสถาปัตยกรรม Zero Audio Storage at Rest ร่วมกับหลักการออกแบบเพื่อความเป็นส่วนตัว (Privacy by Design) โดยประกอบด้วยกลไกสำคัญ 3 ประการ คือ (1) การประมวลผลสัญญาณเสียงเพื่อสกัดความถี่ $F_0$ และทำนายวรรณยุกต์จะดำเนินการภายในหน่วยความจำชั่วคราว (In-Memory Processing) และทำลายบัฟเฟอร์เสียงทิ้งทันทีหลังสกัดค่าตัวเลขเสร็จสิ้น (2) ระบบ PDPA Consent Gatekeeper จะตรวจสอบสถานะการให้ความยินยอมของผู้เรียนก่อนบันทึกข้อมูล Telemetry ทุกครั้ง หากผู้เรียนยังไม่ให้ความยินยอมหรือถอนความยินยอม ระบบจะปฏิเสธการบันทึกข้อมูลลงคลังข้อมูลทันที และ (3) การจัดเก็บประวัติการขอความยินยอมและการถอนความยินยอมพร้อมรหัสแฮชของที่อยู่ไอพี (SHA-256 IP Hash) ลงในตารางตรวจสอบ (user_consent_logs) เพื่อความโปร่งใสและตรวจสอบย้อนกลับได้

3.1.4 โมเดลการติดตามความเชี่ยวชาญของผู้เรียน (Mastery & Knowledge Tracing) และระบบแนะนำบทเรียนซ่อมเสริม

ในการประเมินว่าผู้เรียนมีความเชี่ยวชาญ (Mastery) ในหน่วยเสียงหรือวรรณยุกต์ใดอย่างแท้จริง การใช้ค่าเฉลี่ยเลขคณิตแบบธรรมดา (Simple Arithmetic Mean) ของคะแนนทุกครั้งตั้งแต่อดีตมีข้อเสียสำคัญคือ คะแนนที่ต่ำในช่วงเริ่มต้นฝึกหัดจะฉุดรั้งคะแนนรวมไว้ แม้ว่าในระยะหลังผู้เรียนจะสามารถออกเสียงได้อย่างถูกต้องต่อเนื่องแล้วก็ตาม โครงงานนี้จึงได้นำโมเดล ค่าเฉลี่ยเคลื่อนที่แบบถ่วงน้ำหนักเอ็กซ์โพเนนเชียล (Exponential Moving Average: EMA Mastery Model) [6] มาใช้ในการติดตามความเชี่ยวชาญของผู้เรียน โดยให้น้ำหนักกับผลการฝึกครั้งล่าสุดมากกว่าอดีตตามค่าพารามิเตอร์การเรียนรู้ $\alpha \in (0, 1)$ (ในระบบกำหนดค่าเริ่มต้น $\alpha = 0.30$) ดังสมการที่ (3.4)

$$M_t = \alpha \cdot S_t + (1 - \alpha) \cdot M_{t-1}$$

โดยที่ $M_t$ คือคะแนนความเชี่ยวชาญสะสมหลังการฝึกครั้งที่ $t$, $S_t$ คือคะแนนการออกเสียงในครั้งที่ $t$ และ $M_{t-1}$ คือคะแนนความเชี่ยวชาญสะสมก่อนหน้า

อย่างไรก็ตาม ความเชี่ยวชาญที่ผู้เรียนเคยทำได้ย่อมเสื่อมถอยลงตามกาลเวลาหากไม่ได้รับการทบทวน ตาม ทฤษฎีเส้นโค้งการลืมของเอ็บบิงเฮาส์ (Ebbinghaus Forgetting Curve) [7] ระบบจึงได้ผสานสมการการคงอยู่ของความจำ (Memory Retention: $R$) เข้ากับความแข็งแกร่งของความจำ ($S_{\text{stability}}$ ซึ่งเพิ่มขึ้นตามจำนวนครั้งที่ผู้เรียนทบทวนสำเร็จต่อเนื่อง) และระยะเวลาที่ผ่านไปนับจากการฝึกครั้งล่าสุด ($\Delta t$ หน่วยเป็นวัน) ดังสมการที่ (3.5) และแสดงลักษณะกราฟการคงอยู่ของความรู้และการทบทวนแบบเว้นระยะ (Spaced Repetition) ในรูปที่ 3.2

$$R(\Delta t) = e^{-\frac{\Delta t}{S_{\text{stability}}}}, \quad \text{โดยที่ } S_{\text{stability}} = S_0 \cdot (1 + 0.5 \cdot \min(k, 10)) \cdot \left(0.5 + \frac{M_t}{100}\right)$$

เมื่อนำค่าความเชี่ยวชาญสะสม $M_t$ มาคูณกับอัตราการคงอยู่ของความจำ $R(\Delta t)$ จะได้ คะแนนความเชี่ยวชาญปรับแก้ตามเวลา (Effective Mastery Score: $M_{\text{eff}} = M_t \cdot R(\Delta t)$) หากค่า $M_{\text{eff}} < 75\%$ หรือค่า $R(\Delta t) < 70\%$ ระบบจะตั้งสถานะหน่วยเสียงหรือคำศัพท์นั้นว่า "ควรทบทวน (needsReview = true)" และส่งรายการหน่วยเสียงพยัญชนะต้นและวรรณยุกต์ที่อ่อนไปยัง ระบบแนะนำบทเรียนซ่อมเสริม (Adaptive Remedial & Student Coach Engine) ซึ่งใช้อัลกอริทึมการให้คะแนนความสอดคล้องแบบถ่วงน้ำหนัก (Multi-Criteria Rule-Based Scoring) โดยคำศัพท์ที่มีทั้งพยัญชนะต้นตรงกับจุดอ่อนและมีวรรณยุกต์ตรงกับจุดอ่อน (โดยเฉพาะคำที่มีกฎ Tone Sandhi 3+3) จะได้รับคะแนนลำดับความสำคัญสูงสุดในการนำมาสร้างเป็นการ์ดฝึกซ่อมเสริมรายบุคคล

3.1.5 สถิติเพื่อการประเมินผลสัมฤทธิ์ทางการเรียน (Paired Sample $t$-test, Cohen's $d$ และ Hake's Gain)

เพื่อพิสูจน์ผลสัมฤทธิ์ทางการเรียนของผู้เรียนจากการใช้งานระบบอย่างเป็นวิทยาศาสตร์ โครงงานนี้ได้ฝังโมดูลการคำนวณสถิติเชิงอนุมานและจิตมิติไว้ในระบบวิเคราะห์ข้อมูล (src/lib/analytics/statisticalEngine.ts) โดยใช้สถิติมาตรฐาน 3 ส่วน ได้แก่

  1. การทดสอบค่าทีแบบกลุ่มตัวอย่างไม่อิสระ (Paired Sample $t$-test): ใช้เปรียบเทียบค่าเฉลี่ยของคะแนนทดสอบก่อนเรียน (Pre-test: $X_{\text{pre}}$) และคะแนนทดสอบหลังเรียน (Post-test: $X_{\text{post}}$) ของผู้เรียนคนเดียวกันจำนวน $n$ คน โดยกำหนดผลต่างรายบุคคล $d_i = X_{\text{post}, i} - X_{\text{pre}, i}$ ค่าเฉลี่ยผลต่าง $\bar{d}$ และส่วนเบี่ยงเบนมาตรฐานของผลต่าง $s_d$ สามารถคำนวณค่าสถิติ $t$ ที่องศาอิสระ $df = n - 1$ ได้ดังสมการที่ (3.6)

$$t = \frac{\bar{d}}{s_d / \sqrt{n}}, \quad \text{โดยที่ } s_d = \sqrt{\frac{\sum_{i=1}^{n} (d_i - \bar{d})^2}{n - 1}}$$

  1. ขนาดอิทธิพลของโคเฮน (Cohen's $d$ Effect Size): ใช้บอกขนาดความสำคัญในทางปฏิบัติของพัฒนาการที่เกิดขึ้นโดยไม่ขึ้นกับขนาดกลุ่มตัวอย่าง คำนวณจากอัตราส่วนระหว่างค่าเฉลี่ยของผลต่างต่อส่วนเบี่ยงเบนมาตรฐานของผลต่าง ($d = \bar{d} / s_d$) โดยมีเกณฑ์การแปลผลตามแนวคิดของ Cohen (1988) [8] คือ $|d| \ge 0.80$ หมายถึงขนาดอิทธิพลระดับสูง (Large Effect), $0.50 \le |d| < 0.80$ ระดับปานกลาง (Medium Effect) และ $0.20 \le |d| < 0.50$ ระดับต่ำ (Small Effect)
  1. ค่าพัฒนาการสัมพัทธ์ของเฮก (Hake's Normalized Gain: $\langle g \rangle$): เป็นตัวชี้วัดมาตรฐานในงานวิจัยเทคโนโลยีการศึกษาที่เสนอโดย Hake (1998) [9] เพื่อวัดว่าผู้เรียนสามารถพัฒนาคะแนนเพิ่มขึ้นเป็นสัดส่วนเท่าใดของคะแนนที่ยังขาดอยู่จากคะแนนเต็ม 100 คะแนน ดังสมการที่ (3.7) โดยแบ่งเกณฑ์เป็นพัฒนาการระดับสูง ($\langle g \rangle \ge 0.70$), ระดับปานกลาง ($0.30 \le \langle g \rangle < 0.70$) และระดับต่ำ ($\langle g \rangle < 0.30$)

$$\langle g \rangle = \frac{\bar{X}_{\text{post}} - \bar{X}_{\text{pre}}}{100 - \bar{X}_{\text{pre}}}$$

สรุปความสอดคล้องและการนำแนวคิดและทฤษฎีไปประยุกต์ใช้ในโครงงาน:

จากการศึกษาแนวคิดและทฤษฎีทั้ง 5 ด้านข้างต้น ผู้จัดทำได้นำกรอบวงจร Learning Analytics มาใช้เป็นโครงสร้างหลักในการกำหนดคำถามการเรียนรู้ LQ1–LQ8 นำทฤษฎีสัทศาสตร์ภาษาจีนกลาง มาตรวัดระดับเสียง Chao's Pitch Scale (1–5) และสมการ GOP/PER มาสร้างเป็นโมดูลอนุกรมวิธานความผิดพลาด (Error Taxonomy) ที่จำแนกปัญหาพยัญชนะม้วนลิ้นและวรรณยุกต์ของผู้เรียนชาวไทย นำมาตรฐาน xAPI (IEEE 9274.1.1) ร่วมกับหลักการ PDPA Zero Audio Storage มาออกแบบโครงสร้างการจัดเก็บข้อมูลที่ปลอดภัยไร้ไฟล์เสียงดิบ นำสมการ EMA Mastery และเส้นโค้งการลืมของเอ็บบิงเฮาส์มาใช้ในโมเดลผู้เรียนเพื่อสั่งการระบบแนะนำคำศัพท์ซ่อมเสริมอัตโนมัติ และนำสมการสถิติ Paired Sample $t$-test, Cohen's $d$ และ Hake's Gain มาเขียนเป็นเอนจินคำนวณผลสัมฤทธิ์ทางการเรียนแบบเรียลไทม์บนแดชบอร์ดผู้สอน

3.2 เครื่องมือ ภาษา และเทคโนโลยีที่ใช้ในการพัฒนา

ในการพัฒนาระบบวิเคราะห์ข้อมูลการเรียนรู้และแดชบอร์ดวินิจฉัยการออกเสียงภาษาจีนเชิงสัทศาสตร์ ผู้จัดทำได้เลือกใช้เครื่องมือ ภาษาโปรแกรม และเทคโนโลยีสมัยใหม่ ดังนี้

  1. SvelteKit และ Svelte 5 (Runes Reactivity): เฟรมเวิร์กการพัฒนาเว็บแอปพลิเคชันแบบ Full-Stack ที่คอมไพล์โค้ดเป็น JavaScript ขนาดเล็กโดยไม่พึ่งพา Virtual DOM ช่วยให้การเรนเดอร์แผนภูมิเรดาร์ทักษะ 6 มิติ กราฟความถี่เสียง Pitch Contour และตารางวิเคราะห์ข้อมูลขนาดใหญ่บนแดชบอร์ดมีความลื่นไหลสูง พร้อมทั้งใช้สร้าง Server-side API Endpoints (/api/v1/telemetry/, /api/analytics/, /api/admin/*) สำหรับรับและประมวลผลข้อมูล
  2. ภาษา TypeScript: ภาษาโปรแกรมที่ขยายขีดความสามารถของ JavaScript ด้วยระบบตรวจสอบชนิดข้อมูลแบบเข้มงวด (Static Type Checking) ช่วยป้องกันข้อผิดพลาดในการจัดการโครงสร้างข้อมูล xAPI Statement ที่มีความซับซ้อนและการคำนวณทางสถิติใน statisticalEngine.ts
  3. ฐานข้อมูล Turso (libSQL / Distributed Edge SQLite): ระบบฐานข้อมูลหลักของแอปพลิเคชันที่พัฒนาต่อยอดจาก SQLite โดยสถาปัตยกรรมของ Turso รองรับการเข้าถึงข้อมูลผ่านโปรโตคอล HTTP/WebSockets ด้วยความหน่วงต่ำ (Low Latency) เหมาะอย่างยิ่งสำหรับการบันทึกข้อมูล xAPI Telemetry และประวัติการฝึกออกเสียงแบบเรียลไทม์
  4. คลังข้อมูล Neon (Serverless PostgreSQL): ระบบฐานข้อมูลเชิงสัมพันธ์ระดับองค์กรบนระบบคลาวด์ที่นำมาใช้ในสถาปัตยกรรมคลังข้อมูลแบบสองชั้น (Dual-Database Architecture) โดยระบบจะซิงโครไนซ์ข้อมูลวิจัยจาก Turso ไปยัง Neon PostgreSQL แบบอะซิงโครนัส (neonSync.ts) เพื่อรองรับการสืบค้นข้อมูลเชิงวิเคราะห์ขั้นสูงของผู้สอนและนักวิจัยโดยไม่กระทบต่อความเร็วในการใช้งานของผู้เรียน
  5. Interactive SVG & Tailwind CSS Visualization: เทคโนโลยีการจัดรูปแบบส่วนติดต่อผู้ใช้และการสร้างแผนภูมิภาพเชิงโต้ตอบด้วย Scalable Vector Graphics (SVG) ที่เขียนขึ้นเฉพาะสำหรับแสดงเรดาร์ทักษะ 6 มิติ กราฟเปรียบเทียบการแจกแจงคะแนน Pre/Post-test และแผนภูมิกรวยการเลิกเรียนกลางคัน (Drop-off Funnel)

ทั้งนี้ สามารถสรุปเครื่องมือ ภาษา และเทคโนโลยีทั้งหมดที่ใช้ในการพัฒนาระบบพร้อมบทบาทหน้าที่การทำงานได้ดังแสดงในตารางที่ 3.2

3.3 งานวิจัยที่เกี่ยวข้อง

ในการดำเนินโครงงาน ผู้จัดทำได้ทบทวนวรรณกรรมและงานวิจัยที่เกี่ยวข้องทั้งในประเทศและต่างประเทศ โดยแบ่งออกเป็น 3 ประเด็นหลัก ดังนี้

1. งานวิจัยด้านการตรวจจับความผิดพลาดในการออกเสียงและคะแนน GOP ในระบบ CAPT

Witt และ Young (2000) [4] ได้นำเสนอมาตรวัด Goodness of Pronunciation (GOP) สำหรับการประเมินคุณภาพการออกเสียงระดับหน่วยเสียงในผู้เรียนภาษาที่สอง โดยใช้อัตราส่วนความน่าจะเป็นของโมเดลเสียงเพื่อระบุหน่วยเสียงที่ผู้เรียนออกเสียงเพี้ยน ต่อมา Hu และคณะ (2015) [10] ได้พัฒนาโครงข่ายประสาทเทียมสำหรับการคำนวณค่า GOP และการตรวจจับข้อผิดพลาดในการออกเสียงภาษาที่สอง (Mispronunciation Detection and Diagnosis: MDD) โดยชี้ให้เห็นว่าการจำแนกข้อผิดพลาดออกเป็นระดับพยัญชนะต้น สระ และวรรณยุกต์ ช่วยให้ผู้เรียนเข้าใจสาเหตุของการออกเสียงผิดได้ดีกว่าการให้คะแนนรวมเพียงอย่างเดียว สอดคล้องกับงานวิจัยของ Chen และคณะ (2016) [11] ที่ศึกษาระบบ CAPT สำหรับภาษาจีนกลางและพบว่าผู้เรียนชาวต่างชาติที่มีภาษาแม่เป็นภาษาวรรณยุกต์อื่น (เช่น ภาษาไทยหรือภาษาเวียดนาม) มักเกิดการแทรกแซงจากระบบวรรณยุกต์และพยัญชนะในภาษาแม่ โดยเฉพาะกลุ่มพยัญชนะม้วนลิ้น (zh, ch, sh, r) และวรรณยุกต์เสียงที่ 3 (Tone 3: 214) ซึ่งจำเป็นต้องมีอนุกรมวิธานความผิดพลาด (Error Taxonomy) ที่ตรวจจับการแทนที่เสียง (Substitution) และกฎการเปลี่ยนเสียง (Tone Sandhi) โดยเฉพาะ

2. งานวิจัยด้านการวิเคราะห์ข้อมูลการเรียนรู้ (Learning Analytics) และมาตรฐาน xAPI

Serrano-Laguna และคณะ (2017) [5] ได้ศึกษาการประยุกต์ใช้มาตรฐาน Experience API (xAPI) ในสภาพแวดล้อมการเรียนรู้แบบดิจิทัลและเกมการศึกษา (Serious Games & Gamified Learning) โดยพบว่าการจัดเก็บข้อมูลในรูปแบบ Actor-Verb-Object พร้อมการกำหนดส่วนขยายผลลัพธ์ (result.extensions) และบริบท (context.extensions) ช่วยให้สามารถบันทึกทั้งผลสัมฤทธิ์เชิงตัวเลขและพฤติกรรมระหว่างเรียน (เช่น จำนวนครั้งที่ขอคำใบ้ หรือการกดฟังสื่อตัวอย่าง) ลงในคลังข้อมูลเดียวได้อย่างเป็นมาตรฐาน นอกจากนี้ Khalil และ Ebner (2016) [12] ได้ทำการศึกษาประเด็นจริยธรรมและการลดการระบุตัวตน (De-identification & Privacy Preservation) ในระบบ Learning Analytics และเสนอแนวคิดว่าการเก็บข้อมูลการเรียนรู้ที่เกี่ยวข้องกับข้อมูลชีวมิติจะต้องมีระบบจัดการความยินยอม (Consent Management) ที่โปร่งใส และควรสกัดเฉพาะคุณลักษณะเชิงตัวเลขแทนการจัดเก็บข้อมูลดิบที่ระบุตัวตนผู้เรียนได้โดยตรง

3. งานวิจัยด้านโมเดลติดตามความเชี่ยวชาญของผู้เรียนและแดชบอร์ดแนะนำบทเรียนปรับเหมาะ

Pelánek (2017) [6] ได้ศึกษาเปรียบเทียบโมเดลการติดตามความรู้ของผู้เรียน (Learner Modeling & Knowledge Tracing) ในระบบการเรียนรู้แบบปรับเหมาะ (Adaptive Learning Systems) และพบว่าการใช้อัลกอริทึมค่าเฉลี่ยเคลื่อนที่ถ่วงน้ำหนักแบบเอ็กซ์โพเนนเชียล (Exponential Moving Average: EMA) ร่วมกับฟังก์ชันการเสื่อมถอยตามเวลา (Time-Decay / Forgetting Function) มีความแม่นยำในการทำนายความพร้อมของผู้เรียนเทียบเท่าโมเดลที่ซับซ้อน แต่มีความโปร่งใสในการอธิบายผลลัพธ์ (Explainability) บนแดชบอร์ดผู้เรียนและผู้สอนสูงกว่ามาก ช่วยให้ระบบแนะนำบทเรียนซ่อมเสริม (Recommendation Engine) สามารถอธิบายเหตุผล (Explainable Recommendation Reason) ให้ผู้เรียนเข้าใจได้ว่าเหตุใดจึงควรทบทวนคำศัพท์คำนั้น

สรุปความสอดคล้องและการนำงานวิจัยที่เกี่ยวข้องไปประยุกต์ใช้ในโครงงาน:

จากการทบทวนงานวิจัยทั้ง 3 ประเด็นข้างต้น ผู้จัดทำได้นำแนวคิดการคำนวณคะแนน GOP และการจำแนกความผิดพลาด MDD ของ Witt & Young [4], Hu และคณะ [10] และ Chen และคณะ [11] มาสร้างเป็นโมดูล Error Taxonomy สำหรับผู้เรียนชาวไทยที่ตรวจจับการสลับเสียงพยัญชนะม้วนลิ้น (zh/z, ch/c, sh/s) และความคลาดเคลื่อนของวรรณยุกต์เสียงที่ 3 นำแนวทางการออกแบบโครงสร้าง xAPI Statement ของ Serrano-Laguna และคณะ [5] ร่วมกับแนวคิดการคุ้มครองความเป็นส่วนตัวของ Khalil & Ebner [12] มาพัฒนาเป็นท่อส่งข้อมูล xAPI Telemetry ภายใต้สถาปัตยกรรม PDPA Zero Audio Storage และนำโมเดล EMA ร่วมกับฟังก์ชันการลืมตามเวลาของ Pelánek [6] มาพัฒนาเป็นโมเดลผู้เรียนและระบบ Adaptive Remedial Engine ที่แสดงเหตุผลการแนะนำคำศัพท์ซ่อมเสริมอย่างชัดเจนบนแดชบอร์ดผู้เรียนและผู้สอน

บทที่ 4 การวิเคราะห์และออกแบบระบบ

ในบทนี้จะกล่าวถึงการวิเคราะห์ความต้องการของระบบ การกำหนดกรอบคำถามการเรียนรู้ (Learning Questions: LQ1–LQ8) การวิเคราะห์ขั้นตอนการทำงานของระบบ (Flowchart และ Algorithms) การออกแบบสถาปัตยกรรมระบบและคลังข้อมูลตามมาตรฐาน xAPI ภายใต้มาตรการคุ้มครองข้อมูลส่วนบุคคล (PDPA) การออกแบบส่วนติดต่อผู้ใช้ของแดชบอร์ดผู้เรียนและผู้สอน ตลอดจนการออกแบบเกณฑ์การวัดและประเมินผลการดำเนินงาน โดยมีรายละเอียดดังต่อไปนี้

ระบบการจำแนกความผิดพลาดทางสัทศาสตร์ (src/lib/pronunciation.ts) ทำหน้าที่แยกคำศัพท์พินอินเป้าหมายออกเป็นพยางค์ และแบ่งแต่ละพยางค์ออกเป็น 2 หน่วยเสียงย่อย ได้แก่ พยัญชนะต้น (Initial / Shengmu) จากชุดพยัญชนะมาตรฐาน 23 เสียง (โดยตรวจสอบพยัญชนะควบ 2 ตัวอักษร zh, ch, sh ก่อนพยัญชนะเดี่ยว z, c, s) และ สระพร้อมวรรณยุกต์ (Final + Tone) จากนั้นจึงเปรียบเทียบกับหน่วยเสียงที่ระบบรู้จำได้จริงและจำแนกสถานะความผิดพลาดออกเป็น 4 ประเภทตามอนุกรมวิธานความผิดพลาด (Error Taxonomy) ดังแสดงในตารางที่ 4.2

ตารางที่ 4.2 อนุกรมวิธานความผิดพลาดทางสัทศาสตร์ (Error Taxonomy) และเกณฑ์การจำแนกสถานะ

สถานะความผิดพลาด (Status)ความหมายเชิงสัทศาสตร์เงื่อนไขการตรวจจับตัวอย่างความผิดพลาดของผู้เรียนไทย
correctออกเสียงได้ถูกต้องตรงตามเป้าหมายtarget === recognized และคะแนน GOP $\ge$ เกณฑ์เป้าหมาย sh อ่านเป็น sh
substitutionออกเสียงแทนที่หรือสับสนกับหน่วยเสียงอื่นtarget !== recognized (ทั้งคู่ไม่เป็นค่าว่าง)เป้าหมาย zh แต่ออกเสียงเป็น z, ch $\rightarrow$ c
omissionออกเสียงตกหล่นหรือขาดหายไปมีหน่วยเสียงเป้าหมาย แต่ recognized เป็นค่าว่างตกหล่นพยัญชนะสะกดท้ายพยางค์ -n / -ng
insertionมีเสียงแปลกปลอมแทรกเกินเข้ามาไม่มีหน่วยเสียงเป้าหมาย แต่ตรวจพบเสียงเกินแทรกเสียงสระเกินท้ายคำภาษาจีน

สำหรับการคำนวณตัววัดคุณภาพการออกเสียงเชิงกำหนด (Deterministic Acoustic Metrics) ใน src/lib/analytics/statisticalEngine.ts ระบบคำนวณค่าตัวชี้วัดหลัก 3 ค่า ได้แก่

  1. อัตราความผิดพลาดของหน่วยเสียง ($\text{PER}$): คำนวณจากสัดส่วนจำนวนหน่วยเสียงที่มีสถานะ substitution, omission, หรือ insertion หารด้วยจำนวนหน่วยเสียงเป้าหมายทั้งหมดในคำศัพท์
  2. คะแนนความชัดเจนและรูปร่างวรรณยุกต์ ($S_{\text{clarity}}$ และ $S_{\text{contour}}$): ใช้ค่าความมั่นใจคาบเวลาจากอัลกอริทึม YIN ร่วมกับการแปลงความถี่ $F_0$ เป็นมาตรวัด Chao Scale 1–5 เพื่อตรวจสอบความสอดคล้องของระดับเสียงและทิศทางความชัน (Slope)
  3. คะแนน Goodness of Pronunciation ($\text{GOP}$): คำนวณค่าเฉลี่ยถ่วงน้ำหนักระหว่างความแม่นยำของหน่วยเสียงพยัญชนะ สระ และความแม่นยำของวรรณยุกต์ ให้อยู่ในช่วง 0–100 คะแนน

4.2.3 อัลกอริทึมโมเดลผู้เรียนและระบบแนะนำคำศัพท์ซ่อมเสริม (Remedial & Student Coach Engine)

เพื่อเปลี่ยนผลวินิจฉัยเชิงสัทศาสตร์ให้เป็นแนวทางการฝึกซ่อมเสริมรายบุคคล ระบบประกอบด้วย 2 โมดูลหลักที่ทำงานร่วมกัน ดังแสดงผังงานอัลกอริทึมในรูปที่ 4.2

  1. โมเดลติดตามความเชี่ยวชาญ (EMA Mastery & Ebbinghaus Retention): คำนวณระดับความเชี่ยวชาญของแต่ละหน่วยเสียงและคำศัพท์ด้วยสมการ $M_t = 0.30 \cdot S_t + 0.70 \cdot M_{t-1}$ ร่วมกับอัตราการคงอยู่ของความจำ $R(\Delta t) = e^{-\Delta t / S_{\text{stability}}}$ เพื่อระบุหน่วยเสียงที่ผู้เรียนยังคงอ่อน (weakPhonemes) และวรรณยุกต์ที่ควรฝึกซ้ำ (weakTones)
  2. ระบบแนะนำคำศัพท์ซ่อมเสริม (src/lib/analytics/remedialEngine.ts): นำรายการจุดอ่อน (weakPhonemes และ weakTones) มาจับคู่กับคลังคำศัพท์ HSK 1–3 ทั้ง 1,000 คำ โดยให้คะแนนลำดับความสำคัญแบบถ่วงน้ำหนัก คำศัพท์ที่ตรงทั้งพยัญชนะต้นที่เป็นจุดอ่อนและวรรณยุกต์ที่เป็นจุดอ่อน (รวมถึงคำที่มีกฎ Tone Sandhi 3+3 เมื่อวรรณยุกต์เสียงที่ 3 อ่อน) จะถูกจัดอันดับสูงสุดและคัดเลือกมาสูงสุด 6 การ์ด พร้อมคำอธิบายเหตุผลภาษาไทยที่เข้าใจง่าย
  3. ระบบโค้ชผู้เรียนอัจฉริยะ (src/lib/analytics/studentCoachEngine.ts): รวบรวมข้อมูลทักษะทั้ง 6 ด้านของผู้เรียน (GOP, วรรณยุกต์ 4 เสียง, คัดอักษรจีน, บทสนทนา AI, ความจำ Flashcard, และด่าน Quest) มาสร้างคำแนะนำเชิงปฏิบัติการเรียงตามระดับความเร่งด่วน (high, medium, low)

4.3 การออกแบบระบบงาน

4.3.1 สถาปัตยกรรมระบบ (System Architecture)

ระบบวิเคราะห์ข้อมูลการเรียนรู้ได้รับการออกแบบในลักษณะ คลังข้อมูลแบบสองชั้นและสถาปัตยกรรมแยกส่วนความรับผิดชอบ (Dual-Database xAPI Telemetry Architecture) โดยแบ่งออกเป็น 3 ชั้น ได้แก่

  1. ชั้นส่วนหน้าและการดักจับข้อมูล (Client & Telemetry Adapter Layer): ทำงานบนเว็บเบราว์เซอร์ด้วย SvelteKit รับผิดชอบการสกัดค่าเสียงในหน่วยความจำ แปลงผลลัพธ์ผ่าน adapter.ts และแสดงผลแดชบอร์ดผู้เรียน/ผู้สอน
  2. ชั้นประมวลผลและคัดกรองความปลอดภัย (SvelteKit API & PDPA Gatekeeper Layer): ประกอบด้วย Endpoint /api/v1/consent, /api/v1/telemetry/score-ingest, /api/v1/telemetry/stage-event, /api/analytics/pronunciation, และ /api/admin/export ที่ตรวจสอบสิทธิ์ Session, Rate Limiting และความยินยอม PDPA ก่อนเขียนข้อมูล
  3. ชั้นคลังข้อมูลสองชั้น (Dual Data Warehouse Layer): ใช้ฐานข้อมูลหลัก Turso (libSQL) เพื่อความเร็วในการเขียน-อ่านแบบ Edge Latency ต่ำ และซิงโครไนซ์ข้อมูลวิจัยไปยัง Neon (Serverless PostgreSQL) เพื่อรองรับการสืบค้นเชิงวิเคราะห์ขนาดใหญ่และการส่งออกข้อมูลวิจัยในรูปแบบ CSV และ JSONL ดังแสดงสถาปัตยกรรมระบบในรูปที่ 4.3

4.4 การออกแบบการวัดและประเมินผลการดำเนินงาน

เพื่อประเมินประสิทธิภาพของระบบที่พัฒนาขึ้นอย่างครอบคลุมทั้งเชิงเทคนิค เชิงผลสัมฤทธิ์ทางการเรียน และเชิงความพึงพอใจของผู้ใช้งาน ผู้จัดทำได้กำหนดเกณฑ์การวัดและประเมินผลออกเป็น 3 ด้าน ดังนี้

  1. การประเมินความถูกต้องของท่อส่งข้อมูล xAPI Telemetry และมาตรการ PDPA: ตรวจสอบความสมบูรณ์ของโครงสร้าง JSON ตามมาตรฐาน xAPI 1.0.3 (Actor, Verb, Object, Result, Context) อัตราความสำเร็จของการปฏิเสธข้อมูลเมื่อผู้ใช้ยังไม่ให้ความยินยอม (100% Gatekeeper Enforcement) และการตรวจสอบคลังข้อมูล Turso และ Neon เพื่อยืนยันว่าไม่มีการจัดเก็บไฟล์เสียงดิบ (0 Audio Blobs Stored)
  2. การประเมินผลสัมฤทธิ์ทางการเรียน (Pre-test / Post-test Evaluation): นำผลคะแนนทดสอบก่อนเรียนและหลังเรียนของผู้เรียนกลุ่มทดลองมาวิเคราะห์ด้วยโมดูล statisticalEngine.ts เพื่อหาค่าเฉลี่ย ($\bar{X}$), ส่วนเบี่ยงเบนมาตรฐาน ($S.D.$), สถิติทดสอบ Paired Sample $t$-test ที่ระดับนัยสำคัญทางสถิติ $\alpha = 0.01$, ขนาดอิทธิพล Cohen's $d$, และค่าพัฒนาการสัมพัทธ์ Hake's Normalized Gain ($\langle g \rangle$)
  3. การประเมินความพึงพอใจและการใช้งานระบบ (Usability & Satisfaction Evaluation): ใช้แบบสอบถามมาตราส่วนประมาณค่า 5 ระดับ (Likert Scale) โดยกำหนดเกณฑ์การแปลความหมายระดับคะแนนเฉลี่ยดังแสดงในตารางที่ 4.10

ช่วงคะแนนเฉลี่ย ($\bar{X}$)ระดับความพึงพอใจ / ประสิทธิภาพความหมายในการแปลผล

ผู้จัดทำได้พัฒนาท่อส่งข้อมูลพฤติกรรมการเรียนรู้ (Telemetry Pipeline) ร่วมกับระบบคัดกรองความยินยอมส่วนบุคคล (PDPA Consent Gatekeeper) ในแอปพลิเคชัน "语 ปากจีน" เสร็จสมบูรณ์ตามมาตรฐาน ADL xAPI 1.0.3 (IEEE 9274.1.1) โดยข้อมูลทุกเหตุการณ์ตั้งแต่การกดฟังเสียงตัวอย่าง (experienced) การฝึกออกเสียงรายพยางค์ (attempted) ไปจนถึงการประเมินคะแนนระดับคำศัพท์ (scored) จะถูกแปลงผ่าน src/lib/telemetry/adapter.ts และ src/lib/xapi.ts และจัดเก็บลงในฐานข้อมูลหลัก Turso (libSQL) พร้อมซิงโครไนซ์ไปยังคลังข้อมูล Neon (PostgreSQL) เพื่อรองรับการวิเคราะห์เชิงลึก

ระบบวิเคราะห์ข้อผิดพลาดทางสัทศาสตร์ (Error Taxonomy) โมเดลผู้เรียน (EMA Mastery & Ebbinghaus Retention) และระบบแนะนำคำศัพท์ซ่อมเสริมอัตโนมัติ (remedialEngine.ts และ studentCoachEngine.ts) ได้รับการพัฒนาและบูรณาการเข้ากับแดชบอร์ดผู้เรียน (/analytics) และแดชบอร์ดผู้สอน (/admin) เป็นที่เรียบร้อย

  1. ผลการทดสอบความแม่นยำของระบบแนะนำคำศัพท์ซ่อมเสริม (Adaptive Remedial Engine): จากผลการทดสอบระบบในรายงาน Benchmark ของโครงการ (benchmark/BENCHMARK_REPORT.md) พบว่าอัลกอริทึมสามารถจับคู่จุดอ่อนระดับพยัญชนะต้นและวรรณยุกต์ของผู้เรียนเข้ากับคลังคำศัพท์ HSK 1–3 จำนวน 1,000 คำ ได้ด้วยความแม่นยำในการตรงตามจุดอ่อน (Target Weakness Match Precision) สูงถึง 100.00% โดยคัดเลือกการ์ดคำศัพท์ซ่อมเสริมที่มีประสิทธิภาพสูงสุดจำนวน 6 การ์ดต่อรอบ พร้อมคำอธิบายเหตุผลและคู่มือการจัดวางอวัยวะออกเสียงภาษาไทย ดังแสดงในรูปที่ 5.2
  2. ผลการพัฒนาแดชบอร์ดผู้เรียน (/analytics): แสดงแผนภูมิเรดาร์ทักษะ 6 มิติ (6-Axis Skill Radar) การ์ดคำแนะนำจาก AI Coach เรียงลำดับความสำคัญ (High, Medium, Low) และการ์ดคำศัพท์ซ่อมเสริมรายบุคคลได้อย่างชัดเจนและตอบสนองรวดเร็ว
  3. ผลการพัฒนาแดชบอร์ดผู้สอนและผู้ดูแลระบบ (/admin): ประกอบด้วยมุมมองวิเคราะห์ข้อมูลเชิงลึก 12 มุมมอง ครอบคลุมการแจกแจงข้อผิดพลาดทางสัทศาสตร์ กราฟเปรียบเทียบคะแนน Pre-test / Post-test ดังแสดงในรูปที่ 5.3 และหน้าต่างวิเคราะห์ผู้เรียนรายบุคคลแบบ 360 องศา (Learner 360 Profile Modal) ดังแสดงในรูปที่ 5.4

จากการเก็บข้อมูลการใช้งานและประเมินผลในระบบ (รวมถึงชุดข้อมูลประเมินผลผู้เรียนจำนวน $N = 100$ คน ตามกรอบคำถามการเรียนรู้ LQ1–LQ8) ระบบสามารถสรุปผลการวิเคราะห์ข้อมูลเชิงประจักษ์เพื่อตอบคำถามการเรียนรู้ทั้ง 8 ข้อได้ดังแสดงในตารางที่ 5.2 และแสดงผลการวิเคราะห์ความผิดพลาดจำแนกตามกลุ่มหน่วยเสียงและวรรณยุกต์ดังตารางที่ 5.4

5.2 สรุปผลการดำเนินงาน

จากการดำเนินโครงงานสหกิจศึกษาเรื่อง การพัฒนาระบบวิเคราะห์ข้อมูลการเรียนรู้และแดชบอร์ดวินิจฉัยการออกเสียงภาษาจีนเชิงสัทศาสตร์ตามมาตรฐาน xAPI ภายใต้การคุ้มครองข้อมูลส่วนบุคคล สามารถสรุปผลสัมฤทธิ์เทียบกับวัตถุประสงค์ทั้ง 4 ประการได้ดังนี้

  1. บรรลุวัตถุประสงค์ข้อที่ 1: สามารถกำหนดคำถามการเรียนรู้เชิงประจักษ์ (LQ1–LQ8) ออกแบบโครงสร้างข้อมูลเหตุการณ์การเรียนรู้ตามมาตรฐาน xAPI (IEEE 9274.1.1) และพัฒนาระบบคลังข้อมูลแบบสองชั้น (Turso libSQL และ Neon PostgreSQL) ร่วมกับระบบ PDPA Consent Gatekeeper ที่ไม่จัดเก็บไฟล์เสียงดิบของผู้เรียน (Zero Audio Storage at Rest) ได้สำเร็จ 100%
  2. บรรลุวัตถุประสงค์ข้อที่ 2: สามารถสร้างอนุกรมวิธานความผิดพลาดทางสัทศาสตร์ (Error Taxonomy: correct, substitution, omission, insertion) และโมดูลคำนวณตัววัดคุณภาพการออกเสียง GOP, PER, YIN Clarity และ Chao's Pitch Scale (1–5) ที่สามารถจำแนกจุดอ่อนเฉพาะทางของผู้เรียนชาวไทยได้อย่างแม่นยำ
  3. บรรลุวัตถุประสงค์ข้อที่ 3: สามารถพัฒนาโมเดลติดตามความเชี่ยวชาญของผู้เรียนด้วยวิธี EMA Mastery ($\alpha = 0.30$) ร่วมกับสมการเส้นโค้งการลืมของเอ็บบิงเฮาส์ และระบบ Adaptive Remedial Engine ที่แนะนำคำศัพท์ซ่อมเสริม 6 การ์ดตรงตามจุดอ่อนของผู้เรียนได้แม่นยำ 100%
  4. บรรลุวัตถุประสงค์ข้อที่ 4: สามารถพัฒนาแดชบอร์ดผู้เรียน (/analytics) และแดชบอร์ดวินิจฉัยผู้สอน 12 มุมมอง (/admin) พร้อมเครื่องมือสถิติเชิงอนุมานในตัว (Paired Sample $t$-test, Cohen's $d$, Hake's Gain) ที่ช่วยให้ผู้สอนและนักวิจัยวิเคราะห์ผลสัมฤทธิ์ทางการเรียนได้ทันที

5.3 ข้อจำกัดของโครงงาน

  1. ความแม่นยำขึ้นอยู่กับคุณภาพไมโครโฟนและเสียงรบกวนสภาพแวดล้อม: แม้ระบบวิเคราะห์ข้อมูลจะไม่เก็บไฟล์เสียงดิบ แต่ค่าตัวเลขสัทศาสตร์ (GOP, $F_0$, Clarity) ที่ส่งเข้าสู่ระบบ Learning Analytics ยังคงได้รับผลกระทบหากผู้เรียนฝึกพูดในสภาพแวดล้อมที่มีเสียงรบกวนสูง
  2. ขอบเขตของคำศัพท์และการซ่อมเสริมจำกัดอยู่ที่ระดับ HSK 1–3: อนุกรมวิธานความผิดพลาดและคลังคำศัพท์ซ่อมเสริมของระบบในปัจจุบันครอบคลุมคลังคำศัพท์มาตรฐาน HSK ระดับ 1–3 จำนวน 1,000 คำ ยังไม่ครอบคลุมคำศัพท์ระดับสูง (HSK 4–6)
  3. การปรับแต่งพารามิเตอร์ของโมเดลผู้เรียนยังเป็นแบบค่าคงที่ (Heuristic Parameters): ค่าปัจจัยการปรับเรียบ ($\alpha = 0.30$) และค่าความแข็งแกร่งเริ่มต้นของความจำในสมการเอ็บบิงเฮาส์ยังกำหนดเป็นค่าคงที่สำหรับผู้เรียนทุกคน ยังไม่ได้ปรับค่าพารามิเตอร์เฉพาะรายบุคคลโดยอัตโนมัติ

5.4 ปัญหาและข้อเสนอแนะ

5.4.1 ปัญหาที่พบในการดำเนินงาน

  1. ความไม่สอดคล้องของรูปแบบผลลัพธ์จากโมดูลประมวลผลเสียงหลายแหล่ง: ในระหว่างการเชื่อมโยงข้อมูลจากระบบฝึกพูด (Web Speech API, YIN Pitch Tracking, ONNX Tone Predictor และ LLM Evaluation) พบว่าแต่ละโมดูลส่งข้อมูลผลลัพธ์ในโครงสร้างที่แตกต่างกัน ผู้จัดทำจึงแก้ปัญหาด้วยการออกแบบชั้น Telemetry Adapter (src/lib/telemetry/adapter.ts) เพื่อทำหน้าที่แปลงและปรับมาตรฐานข้อมูลทุกแหล่งให้เป็น StandardTelemetryPayload ก่อนแปลงเป็น xAPI Statement
  2. การซิงโครไนซ์ข้อมูลและการรองรับปริมาณการเขียนข้อมูลพร้อมกัน: เมื่อมีผู้เรียนส่งข้อมูล Telemetry พร้อมกันจำนวนมาก การเขียนข้อมูลไปยังฐานข้อมูลวิเคราะห์ (Neon) โดยตรงอาจเพิ่มความหน่วงให้หน้าแอปพลิเคชัน ผู้จัดทำจึงแก้ปัญหาด้วยการใช้ Turso (libSQL) เป็นฐานข้อมูลหลักที่มีความหน่วงต่ำ แล้วใช้กลไก Asynchronous Sync ไปยัง Neon PostgreSQL

5.4.2 ข้อเสนอแนะในการพัฒนาต่อยอด

  1. การพัฒนาโมเดล Deep Knowledge Tracing (DKT) หรือ Bayesian Knowledge Tracing (BKT): เมื่อมีข้อมูล xAPI Statements สะสมในคลังข้อมูล Neon PostgreSQL ในปริมาณมากเพียงพอ สามารถนำข้อมูลดังกล่าวมาฝึกสอนโมเดล Deep Knowledge Tracing เพื่อทำนายโอกาสที่ผู้เรียนจะออกเสียงผิดในคำศัพท์ใหม่ได้อย่างแม่นยำยิ่งขึ้น
  2. การเชื่อมต่อกับ Learning Record Store (LRS) ภายนอก: สามารถเพิ่มตัวส่งต่อข้อมูล (xAPI Forwarder) เพื่อส่งสำเนา xAPI Statements ไปยังระบบบริหารจัดการการเรียนรู้ (LMS) ของสถานศึกษาหรือองค์กรพันธมิตรได้โดยตรง
  3. การขยายระบบไปยังภาษาต่างประเทศอื่นที่มีระบบวรรณยุกต์: สถาปัตยกรรม Error Taxonomy และ Chao's Pitch Scale ที่พัฒนาขึ้นสามารถปรับปรุงตารางหน่วยเสียงเพื่อนำไปประยุกต์ใช้กับการวิเคราะห์การออกเสียงภาษาเวียดนาม หรือภาษาไทยสำหรับชาวต่างชาติได้ในอนาคต

5.5 สรุปผลการปฏิบัติงานสหกิจศึกษา

5.5.1 ประโยชน์ที่ได้รับด้านวิชาการ

  1. ได้นำความรู้ทางทฤษฎีด้านปัญญาประดิษฐ์ วิทยาการข้อมูล สถิติเชิงอนุมาน และวิศวกรรมซอฟต์แวร์ มาประยุกต์ใช้ในการออกแบบระบบ Learning Analytics และระบบแนะนำบทเรียนปรับเหมาะ (Adaptive Recommendation System) ได้อย่างเป็นรูปธรรม
  2. ได้เรียนรู้มาตรฐานข้อมูลการศึกษาระดับสากล (Experience API / IEEE 9274.1.1) การออกแบบอนุกรมวิธานความผิดพลาดทางสัทศาสตร์ (Error Taxonomy) และการออกแบบสถาปัตยกรรมระบบที่สอดคล้องกับกฎหมายคุ้มครองข้อมูลส่วนบุคคล (PDPA Privacy by Design)

5.5.2 ประโยชน์ที่ได้รับด้านการทำงาน

  1. ได้ฝึกทักษะการทำงานร่วมกับทีมวิจัยและพัฒนาในองค์กรเทคโนโลยีชั้นนำ (NECTEC และ AIAT) ผ่านการวางแผนงาน 16 สัปดาห์ การรายงานความก้าวหน้าประจำสัปดาห์ และการสื่อสารข้ามสายงานระหว่างทีมพัฒนาโมเดล AI และทีมออกแบบระบบข้อมูล
  2. ได้พัฒนาทักษะการแก้ปัญหาเชิงวิศวกรรมซอฟต์แวร์ การควบคุมคุณภาพโค้ดด้วย TypeScript การบริหารจัดการฐานข้อมูลบนระบบคลาวด์ และความรับผิดชอบต่อการส่งมอบผลงานจริงตามกำหนดเวลา

  3. เว็บเบราว์เซอร์สมัยใหม่ที่รองรับ Web Audio API และ HTTPS (Google Chrome, Microsoft Edge, Firefox หรือ Safari เวอร์ชันล่าสุด)
